# Cache, species and runtime

These flags name the annotation cache and the reference FASTA, the species and assembly, and the batch size, thread counts and distances of a run. The cache is found as Ensembl VEP finds it, under `--dir_cache`, `--species` and `--cache_version`, or named directly with `--json_cache`. Building or converting a cache is described under [Cache setup](../cache-setup.md), and the genomes beside human, with each cache's release, genetic codes and chromosome names, under [Other species](../cache-species.md). The flags that read data Ensembl ships for human alone are listed under [Species and assembly](#flags-that-read-data-ensembl-ships-for-human-alone).

The flags under [3' shifting](#3-shifting) move an insertion or deletion to its most 3' position on a transcript before it is annotated or described in HGVS, and report how far it moved.

## Cache and offline

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--cache` | String | none | Annotate from the local cache, which vep-rs always does; a directory value is the cache root, as `--dir_cache`, when that flag is absent |
| `--offline` | bool | false | Accepted without effect: vep-rs always runs offline and never contacts a database |
| `--dir` | String | `~/.vep` | Top-level VEP data directory: the cache root when neither `--dir_cache` nor a `--cache` directory is given |
| `--dir_cache` | String | none | Cache root: the cache read is \<dir\_cache\>/\<species\>[\_refseq\|\_merged]/\<cache\_version\>\_\<assembly\>, as Ensembl VEP lays it out (defaults to `--dir`) |
| `--cache_version` | u32 | none | Cache version: the prefix of the cache directory under the species directory (defaults to the VEP release) |
| `--json_cache`, `--full_cache_dir` | String | none | The cache directory itself, the one holding info.json and transcripts/ (built by vep-cache-builder or converted from an Ensembl VEP cache); it is read in place of the `--dir_cache` layout, and only `--assembly` is checked against its info.json |
| `--show_cache_info` | bool | false | Print the cache's source versions as sorted key\<TAB\>value lines and exit; under `--regulatory_gff` a regulatory\_gff line names the first of that flag's file, emars and motifs files |
| `--fasta`, `--fa` | String | none | FASTA file for reference sequence lookup: plain with its .fai, or bgzipped with the .fai and .gzi that samtools faidx writes, each written beside the file when it is missing; a gzip file that is not BGZF is refused. A directory stands for every indexed .fa and .fa.gz in it, read together. Without the flag, the first indexed .fa or .fa.gz by name in the cache directory is used |
| `--fasta_dir` | String | none | Directory holding FASTA files of several species or assemblies: the .fa or .fa.gz whose name carries `--species` and the assembly is used, a toplevel file before any other, a bgzipped file before a plain one and the first by name of two tied on both (where Ensembl VEP keeps the directory listing's order), in place of `--fasta` and of the cache directory's FASTA; when none qualifies the run warns and falls back to `--fasta` or the cache directory's FASTA |
| `--no_fasta` | bool | false | Do not use a FASTA file found in the cache directory |
| `--synonyms` | String | none | Chromosome synonyms file: on each line, whitespace-separated names of one chromosome, the first the reference name; an input chromosome the cache does not name is looked up through its synonyms. Replaces the cache's own chr\_synonyms.txt, which is read when this flag is absent |
| `--sereal` | bool | false | Accepted without effect: vep-rs reads a cache's JSON shards, whatever serialiser its metadata names |

## 3' shifting

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--shift_3prime` | i64 | none | Move each insertion or deletion to its most 3' position on the transcript, over a 1,000-base window of the reference, before its consequence terms, positions, codons and amino acids are computed (1, or any other integer but 0), or annotate it where the input placed it (0); needs a FASTA and stops the run without one. The HGVS notations shift under `--shift_hgvs`, not this flag. The shift runs along the genome only: a transcript whose cached sequence is edited away from the genome is not shifted again along its own sequence |
| `--shift_hgvs` | `0`, `1` | none | Move each insertion or deletion to its most 3' position on the transcript before its HGVSc and HGVSp are built (1, the default), or describe it where the input placed it (0), which also sets `--shift_3prime` to 0 and cannot be combined with `--shift_3prime` or `--shift_genomic` |
| `--shift_genomic` | i64 | none | Under `--shift_3prime` 1, print the shifted position in Location and the shifted sequence in Allele on every row (1, or any other integer but 0), intergenic rows moving towards higher coordinates, or keep the input position (0); without `--shift_3prime` 1 nothing moves |
| `--shift_length` | bool | false | Add the SHIFT\_LENGTH column: under `--shift_3prime` 1, the bases each insertion or deletion moved along the transcript, 0 on every other transcript row of a sequence variant and none on a structural record's rows |

## Species and assembly

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--species`, `-s` | String | `homo_sapiens` | Species: names the cache directory under `--dir_cache`; the Latin name only, with no alias such as human (mus\_musculus, arabidopsis\_thaliana). The genomes compared with Ensembl VEP are the rows of tests/genomes/genomes.tsv, listed on the Supported genomes page of the documentation. The chromosome names of a run are the cache's own: an input name the cache does not hold is looked up through its synonyms file, then with a chr prefix added or removed, so a cache of any species is annotated under its own names |
| `--assembly`, `-a` | String | none | Genome assembly (e.g., GRCh38): chooses among several caches of one version and must equal the cache's own name exactly; hg19 and hg38 are read as GRCh37 and GRCh38. Any other name is the cache's as given. A built-in plugin takes its GRCh37 or GRCh38 hint from the cache's own name, else from this flag: GRCh37, hg19 or 37 and GRCh38, hg38 or 38 give it, in any letter case. Under a name that gives none, each built-in plugin warns, as it loads, that it runs without the hint |
| `--grch37` | bool | false | Annotate against GRCh37: sets `--assembly` GRCh37, over an explicit `--assembly`, as Ensembl VEP's option set does |

### Flags that read data Ensembl ships for human alone

Ensembl ships SIFT and PolyPhen predictions, population frequencies, the MANE, APPRIS, TSL and CCDS attributes and the GENCODE sets for human, and some of them for mouse. A flag that reads such data behaves on a cache of a species that lacks it as Ensembl VEP behaves: refused for SIFT and PolyPhen, which `--everything` switches off, and, on a cache that declares variation columns, for `--af_gnomad`, and otherwise as the table states. A column flag declares its columns in the header and leaves every cell empty, a transcript-set flag drops every transcript, a frequency filter whose population is accepted keeps or drops every record and `--regulatory` writes no regulatory row.

The table lists each flag, its behaviour on a cache without the data, and what the Ensembl release 116 mouse cache (GRCm39) holds, read from its metadata, its chromosome 19 variants and one chromosome 19 transcript shard of 1,222 transcripts.

The chromosome 19 variant counts are recorded in [the cache's count record](../concordance-provenance/mouse-grcm39-chromosome-19-variation-counts.json).

| Flag | On a cache without the data | Mouse at release 116 |
| --- | --- | --- |
| `--sift` | Refused before the input is read: `ERROR: [cache] SIFT not available`; under `--everything` or `--safe` switched off with `INFO: disabling SIFT`, so no SIFT column is written | SIFT is present (`sift b`): predictions print |
| `--polyphen` | As `--sift`, naming PolyPhen | No PolyPhen: refused, or switched off under `--everything` or `--safe` |
| `--af_gnomad` | Refused: `ERROR: [cache] gnomAD data is not available in this cache`, since the cache declares no `gnomADe` column; `--everything` skips the check. On a cache that declares no variation columns the flag is accepted, as Ensembl VEP accepts it: the gnomAD exome columns are declared and every cell is empty | No `gnomADe` column: refused |
| `--af`, `--af_1kg`, `--af_gnomade`, `--af_gnomadg`, `--max_af` | Columns declared, every cell empty: a frequency is written only from a co-located variant that carries it | No frequency column: every cell empty |
| `--check_frequency`, `--filter_common` | No record has frequency data, so `--freq_filter exclude` keeps every record and `include` drops every record; `--freq_pop` accepts `1KG_ALL` alone, any other population is refused as not declared. On a cache that declares no variation columns every `--freq_pop` name is accepted, as Ensembl VEP checks the name only where the cache declares variation columns. On a cache that declares no variation columns the filter is inactive, as in Ensembl VEP: `--freq_filter include` and `exclude` both keep every record, and `FREQS` is empty on every row | The same |
| `--pubmed`, `--var_synonyms` | Columns declared; a cell is filled only where the co-located variant carries a citation or a synonym | Both columns declared and filled where a variant carries one: on chromosome 19, 186 of 2,809,961 variants carry a citation and 19,293 a synonym |
| `--mane`, `--mane_select` | Columns declared, every cell empty | No MANE attribute: every cell empty |
| `--appris`, `--tsl`, `--ccds` | Columns declared, every cell empty | Present: of the shard's 1,222 transcripts, 205 carry APPRIS, 163 a TSL and 117 a CCDS |
| `--gene_phenotype`, `--uniprot`, `--domains` | Columns declared, every cell empty | Present: in the shard, 865 transcripts belong to a gene with a phenotype, 287 carry a UniParc accession and 548 a protein domain |
| `--gencode_basic` | Every transcript is dropped as the cache loads and every record is `intergenic_variant`; the warnings file gets one line, `WARNING: no transcript of the cache carries the gencode_basic attribute; every transcript is filtered` | The attribute is present (GENCODE M39; 612 of the shard's 1,222 transcripts): the set applies |
| `--gencode_primary`, `--flag_gencode_primary` | Ensembl VEP's warning that the option is only available for human on the GRCh38 assembly; `--gencode_primary` then drops every transcript, with the warning above naming `gencode_primary`, and `--flag_gencode_primary` writes an empty `GENCODE_PRIMARY` column | The attribute is present (136 of the shard's 1,222 transcripts): the assembly warning prints and the set or the column applies all the same |
| `--regulatory` | No RegulatoryFeature or MotifFeature row; one warning says the cache holds no regulatory data | Regulatory data is present (83 cell types) |

## Runtime

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--buffer_size` | usize | 5000 | Number of variants to process per batch |
| `--max_sv_size` | i64 | 10000000 | A record whose end minus start exceeds this many bases is oversize, a sequence record included; -1 lifts the limit, as in Ensembl VEP 116. With a FASTA, a \<CNV:TR\> record whose repeat sequence is longer than this stays a symbolic tandem repeat rather than expanding to its alleles (under -1 every one does, and 0 reads as 5000), as in Ensembl VEP 116. Ensembl VEP 116 drops an oversize record before annotation and writes nothing for it in any format; vep-rs annotates it: rows in the default, tab and parquet outputs, its VCF line without consequences, no JSON object (docs/output-formats.md and docs/intended-divergences.md describe the divergence). A region, SPDI or HGVS transcript record whose span exceeds the limit is skipped with Ensembl VEP's warning, as every oversize record is in Ensembl VEP 116; the skip is made as the line is parsed, so it holds under `--dont_skip` too, where Ensembl VEP keeps the feature (`--dont_skip` names the records it cannot keep). An HGVS genomic notation's end minus its start must be smaller than this value, 0 reading as 5000 and -1 as -1 itself, so under -1 a notation written in genome order is skipped, as Ensembl VEP 116 skips it |
| `--fork`, `--threads` | usize | 0 | Number of parallel annotation worker threads (Ensembl VEP forks processes; vep-rs runs threads and is parallel by default). Default 0 = auto: uses the number of available logical CPUs, capped at 32 (one reader thread feeds the workers, so extra workers wait at the batch barrier). On a BGZF input with a .tbi or .csi index beside it whose records inflate to at least 8,000 bytes, `auto` leaves the decompression threads their CPUs: the workers are the available logical CPUs less the decompression thread count, capped at 32 and never fewer than half the capped CPU count. Set to 1 to force single-threaded annotation, or any positive value to pin the worker count; user-supplied values are not capped |
| `--decompression_threads` | String | none | Number of BGZF decompression worker threads for a BGZF-compressed input (a plain gzip input is decompressed on one thread). `0`: the number of available logical CPUs, capped at 10. `auto` chooses the count from the input's inflated bytes per record: a BGZF input with a .tbi or .csi index beside it whose records inflate to at least 8,000 bytes gets 32 workers on an aarch64 host, capped at the available logical CPUs; any other input, and every input on another architecture, gets the 0 rule. Without the flag, an aarch64 host uses `auto` and any other host `0`. A positive value pins the worker count, e.g. `--decompression_threads=1` for single-threaded; a value above the number of available logical CPUs is lowered to that number |
| `--compression_threads` (hidden) | usize | 0 | Number of BGZF deflate worker threads for `--compress_output bgzip`: the output's blocks of at most 64 KiB are deflated on this many threads and written in order by one more. Default 0: uses the number of available logical CPUs, capped at 16. `1` deflates on the thread that writes the output, with no worker thread; a value above the number of available logical CPUs is lowered to that number. `--compress_output gzip` writes its one member on the writing thread whatever this says. The value changes nothing in the uncompressed output but the command line it records; the compressed bytes follow the text alone |
| `--parse_threads` (hidden) | u64 | 0 | Threads of the pool the cache's transcript shards parse on when a chromosome loads, the pool the run's other cache reads outside the annotator pool share; at most 1024; 0 is the pool's built-in width, the number of available logical CPUs. The value changes nothing in the output but the command line it records |
| `--prewarm_ahead` (hidden) | String | 1 | Chromosomes the prewarm helper loads ahead of the one the reader has reached, in the order of the bgzipped input's index: a count (0 loads the reached chromosome alone), or `all` to queue every indexed chromosome the cache holds when the reader starts. A plain or unindexed input has no order to read ahead in. The value changes nothing in the output but the command line it records |
| `--reader_core` (hidden) | String | `auto` | Whether the reader thread, which scans the inflated input text, gets a physical core no other thread of the run may use. `auto` reserves one on a host whose cores run two or more hardware threads, with at least 8 such cores all available to the run and more run threads than cores, once the first 4,096 records have read as at least 8,000 inflated bytes each (a shorter input runs unpinned); `none` never does; a logical CPU number pins the reader there from its first record and reserves that CPU's core whatever the records' width. The knob acts on a VCF input; a parsed format (Ensembl, HGVS, region, SPDI, ID) is read unpinned. The value changes nothing in the output but the command line it records |
| `--pipeline_mode` (hidden) | `batched`, `streaming` | `streaming` | How the batches move through the pipeline. `streaming` hands each batch to the worker pool as independent tasks that annotate and render their own records (and parse them, for a VCF input) and takes the next batch without waiting for them; the writer puts the rendered output back in input order. `batched` annotates and renders each batch on the pool as a whole before the next one starts, while a prefetch stage parses the next batch and reads ahead what its sources can read before it is annotated. A run with plugins or `--custom` sources, or one reading known variants from the cache's variation files or from the `--check_svs` file, uses `batched` whatever this says: plugins and custom sources see a whole batch at once, and each of those sources answers one batch's regions at a time |
| `--pipeline_depth` (hidden) | u64 | 0 | Batches a pipeline stage may hold ahead of the next one, at most 1024; 0 is the built-in depth |
| `--render_task_records` (hidden) | u64 | 0 | Input records per pool task in both pipeline modes (per render task on the plugin path), at most 1,000,000; 0 is the built-in sizing |
| `--writer_strategy` (hidden) | `buffered`, `direct`, `vectored` | `buffered` | How rendered output reaches the file or standard output. `buffered` collects it in a buffer of `--output_buffer_size` bytes; `direct` writes each rendered chunk with one call; `vectored` writes the chunks that are ready together with one vectored call. The strategy changes nothing in the uncompressed output but the command line it records |
| `--output_buffer_size` (hidden) | u64 | 0 | Bytes of the `buffered` writer strategy's buffer, at most 1073741824 (1 GiB); 0 is the built-in size. The other strategies ignore it |
| `--resolved_config` (hidden) | bool | false | Print the resolved runtime knobs and the input's shape as name\<TAB\>value lines and exit without annotating |
| `--distance` | String (comma-separated) | 5000 | Upstream and downstream distance in bp: one integer, or the pair "up,down" (a downstream part written 0 reads as the upstream value) |
| `--tmpdir` | String | none | Accepted without effect: no module of the ensembl-vep repository reads it; Ensembl VEP's FATHMM plugin, which vep-rs does not port, puts its input and output files there; it places no file vep-rs writes |

Flags marked `(hidden)`, 10 on this page, are left out of `--help` and are kept for tuning and diagnosis. The name, the values, the default and the effect of such a flag may change, and the flag may be removed, in any release, however it is given: on the command line, in a configuration file or in a `VEP_<FLAG>` variable ([configuration sources](compatibility.md#configuration-sources)).
