# Filtering, picking and transcript sets

These flags reduce the rows reported per record, allele or gene, flag the ones a pick would drop and filter transcripts by their attributes. The flags under [Alleles and positions](#alleles-and-positions) add the allele columns, trim the alleles and add the total length to the positions. The transcript-set flags select the cache read and the transcript set annotated: the GENCODE basic or primary set, and on a RefSeq or merged cache the RefSeq accessions unless `--all_refseq` keeps every model. The flags under [Reference allele](#reference-allele) choose whether a row's reference allele is the transcript's or the input's.

## Filtering and picking

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--pick` | bool | false | Pick one consequence per variant |
| `--pick_allele` | bool | false | Pick one consequence per variant allele |
| `--per_gene` | bool | false | Pick one consequence per gene |
| `--pick_allele_gene` | bool | false | Pick one consequence per allele per gene |
| `--most_severe` | bool | false | Report only the single most severe consequence |
| `--summary` | bool | false | Report a summary of all consequences |
| `--flag_pick` | bool | false | Flag (but don't remove) non-picked consequences |
| `--flag_pick_allele` | bool | false | Flag non-picked consequences per allele |
| `--flag_pick_allele_gene` | bool | false | Flag non-picked consequences per allele per gene |
| `--pick_order` | `mane_select`, `mane_plus_clinical`, `canonical`, `appris`, `tsl`, `biotype`, `ccds`, `rank`, `length`, `ensembl`, `refseq` (comma-separated) | none | The criteria the pick family compares, in order, as a comma-separated list; a shorter list compares its criteria and then keeps the first transcript in Ensembl VEP's row order (the stable id, then `_` and the database id), and an empty value keeps it at once. Default: mane\_select,mane\_plus\_clinical,canonical,appris,tsl,biotype,ccds,rank,length,ensembl,refseq |
| `--transcript_filter` | String (repeatable) | none | Annotate only the transcripts that pass a filter, in Ensembl VEP's filter grammar: units of `field operator value` joined by `and` and `or`, grouped by parentheses and inverted by `not`; repeated flags are joined by `and`. The fields are the cache's transcript keys, named exactly, in another case, without the leading `_`, or by a unique prefix: `stable_id`, `version`, `biotype`, `start`, `end`, `strand`, `is_canonical`, `source`, `dbID`, `cdna_coding_start`, `cdna_coding_end`, `_gene_stable_id`, `_gene_version`, `_gene_symbol`, `_gene_symbol_source`, `_gene_hgnc_id`, `_ccds`, `_refseq`, `_protein`, `_swissprot`, `_trembl`, `_uniparc`, `_uniprot_isoform`, `_gene_phenotype`, `_source_cache` (`Ensembl` or `RefSeq` on a merged cache's transcripts, undefined elsewhere, so `_s` is a prefix of two keys and names neither), `_gene_symbol_id` (the EntrezGene identifier a RefSeq transcript's symbol is taken from, on a RefSeq or merged cache, undefined elsewhere, so `_gene_symbol_` is a prefix of two keys), `_bam_edit_status` (`ok` or `failed` on a model edited against the cache's alignment file, undefined elsewhere); the object keys `translation` (coding transcripts), `slice`, `attributes`, `_gene`, `_trans_exon_array`, `_variation_effect_feature_cache` and `_vep_lazy_loaded`, which are defined and read meaningfully by `exists` and `nex` alone; and `description`, `coding_region_start` and `coding_region_end`, which the cache leaves undefined. The operators are `is` (`eq`, `=`), `ne` (`!=`), `>`, `<`, `>=`, `<=`, `exists` (`defined`, the default), `nex`, `match` (`matches`, `regex`, `re`), `nre`, `in` (a comma-separated list or a file with one value per line) and `is_child`. `match` and `nre` read their pattern as Perl reads it and compile it with the `regex` crate, case-insensitive and unanchored: a back-reference or another construct the crate cannot express is an error naming the pattern. The grammar drops a `^` and what stands before it in a word, so `^X._` reads as `X._`. A record whose every transcript is filtered out is intergenic |
| `--exclude_predicted` | bool | false | Drop RefSeq's predicted transcript models, the `XM_` and `XR_` accessions, by adding the filter `not stable_id match ^X._` after the `--transcript_filter` values, as Ensembl VEP's option set does. The filter reads every transcript of the run, so the flag takes effect wherever an identifier matches the pattern: on a converted RefSeq or merged cache, on an Ensembl cache whose transcripts are named by RefSeq accession, and on a GTF or GFF3 that holds such models, built into a cache or read beside one. Where none matches, it changes no annotation |

An `in` list of `--transcript_filter` that mixes a number and other text, `gene_hgnc_id in HGNC:2559,1132`, reads a `text:number` or `text(number)` value through its number when its first written entry is a number and whole otherwise ([the class](../divergences/transcript-filter-in-list-numeric-by-hash-order.md)). Ensembl VEP decides by an entry it picks from the list's hash, so write the entries in one shape, `HGNC:2559,HGNC:1132` or `2559,1132`, and both engines keep the same rows.

## Alleles and positions

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--allele_number` | bool | false | Add allele number from input VCF |
| `--show_ref_allele` | bool | false | Show reference allele in output |
| `--uploaded_allele` | bool | false | Add the UPLOADED\_ALLELE column: the record's allele string as uploaded, REF and every ALT joined by / |
| `--ambiguity` | bool | false | Add the AMBIGUITY column: the IUPAC ambiguity code of the record's alleles (R for A/G); absent on an indel or any other allele set without a code |
| `--minimal` | bool | false | Trim every bi-allelic record's alleles from both ends and split a multi-allelic record whose alleles trim into one allele per row, each on its own trimmed span, as Ensembl VEP minimises; switches on `--allele_number` as in Ensembl VEP |
| `--total_length` | bool | false | Append /\<total length\> to the cDNA, CDS and protein positions: the transcript's cDNA length, its coding sequence length and its peptide length. In JSON a single base prints the string "428/1200" as both cdna\_start and cdna\_end, as in Ensembl VEP, and a range prints its start as a number and its end as "430/1200", where Ensembl VEP prints the start as both |

## Transcript sets

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--refseq` | bool | false | Annotate against the RefSeq transcript set. The cache is read under the species directory suffixed \_refseq, or under `--json_cache` as named, and of its models only the RefSeq accessions are kept (a stable id opening with two capitals, an underscore and a digit: NM\_, NR\_, XM\_, XR\_ and the other prefixes; on MT, a mitochondrial gene id) unless `--all_refseq` keeps every model. An HGVS gene name resolves among the RefSeq transcripts before the Ensembl ones. The REFSEQ\_MATCH and REFSEQ\_OFFSET columns are added, and a cache whose models were corrected against an alignment file (BAM-edited) switches `--use_transcript_ref` on with an INFO: line |
| `--merged` | bool | false | Annotate against the merged transcript set, Ensembl and RefSeq models together. The cache is read under the species directory suffixed \_merged, or under `--json_cache` as named; every Ensembl model is kept, and of the RefSeq-sourced models (source\_cache RefSeq) only the RefSeq accessions, unless `--all_refseq` keeps every model. The REFSEQ\_MATCH, SOURCE and REFSEQ\_OFFSET columns are added, and a BAM-edited cache switches `--use_transcript_ref` on with an INFO: line |
| `--all_refseq` | bool | false | Keep every model of a RefSeq or merged cache, the CCDS, EST and gene-symbol ids among them, instead of the RefSeq accessions alone; changes nothing on an Ensembl cache |
| `--gencode_basic` | bool | false | Annotate against the GENCODE basic transcript set alone: a transcript without a gencode\_basic attribute is dropped as the cache loads, before the transcript index is built |
| `--gencode_primary` | bool | false | Annotate against the GENCODE primary transcript set alone: a transcript without a gencode\_primary attribute is dropped as the cache loads; the set exists for human GRCh38 only, so `--assembly` naming another assembly is warned about |
| `--flag_gencode_primary` | bool | false | Add the GENCODE\_PRIMARY column: 1 on a transcript of the GENCODE primary set, empty otherwise; the set exists for human GRCh38 only, so `--assembly` naming another assembly is warned about |

## Reference allele

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--use_transcript_ref` | bool | false | Read each row's reference allele from the transcript instead of the input, and add GIVEN\_REF (the input's reference allele) and USED\_REF (the row's) to the output. The row's allele is the transcript's spliced cDNA over the variant where the variant lies wholly inside the exons, `-` for an insertion, and the input's allele elsewhere; an alternate allele equal to the transcript's sequence takes the terms an allele equal to the reference takes, and the reference row of `--process_ref_homs` is the transcript's allele. Needs `--fasta`, which supplies a non-coding transcript's cDNA; `--use_given_ref` switches it off. A BAM-edited cache, a RefSeq or merged cache whose models were corrected against an alignment file, switches it on by itself with an INFO: line and adds BAM\_EDIT; an edited transcript's allele is cut from its edited cDNA |
| `--use_given_ref` | bool | false | Keep the input's reference allele: switches `--use_transcript_ref` off, and keeps it off on a BAM-edited cache, which otherwise switches it on with an INFO: line. GIVEN\_REF and USED\_REF are not written; BAM\_EDIT stays on an edited transcript's rows in the default and JSON formats |
| `--bam` | String | none | Refused with an error: `--bam` is not supported: Ensembl VEP applies a BAM's alignments to RefSeq transcript models at run time; the RefSeq cache Ensembl distributes already carries those edits, which vep-rs reads from a converted \<species\>\_refseq cache under `--refseq`; a GFF or GTF transcript set of your own is read without the BAM's edits; build a cache from the file and the genome, then annotate against it: vep-cache-builder `--species` \<species\> `--assembly` \<assembly\> `--release` \<N\> `--gtf` \<file\> `--genome-fasta` \<genome.fa\> `--output-dir` \<dir\> (`--gff3` \<file\> for a GFF3), then vep -i \<in\> -o \<out\> `--offline` `--json_cache` \<dir\> `--fasta` \<genome.fa\>; the page docs/cache-from-gtf-or-gff3.md states the route |
