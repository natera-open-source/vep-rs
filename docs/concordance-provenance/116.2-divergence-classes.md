# Divergence classes against Ensembl VEP 116.2

The two comparators of this repository, `scripts/concordance/compare_vep_outputs.py` for the SNP/indel datasets and `scripts/validation/compare_sv_concordance.py` for the structural-variant sets, score vep-rs against one Ensembl VEP release at a time, chosen by `--reference-release`. Under `115.2` they apply the classes the paper documents, unchanged ([docs/intended-divergences.md](../intended-divergences.md)), and write the reports they wrote when the paper was measured, byte for byte. Under `116.2`, the default, they apply the classes on this page. This page is the taxonomy for the 116.2 registry: every class the adjusted figure sets aside or counts when the reference is Ensembl VEP 116.2, with its mechanism in Ensembl VEP's source at that release.

Source citations name the module and line at the 116 release: the `release/116.2` tag of `ensembl-vep` and the `release/116` branch of `ensembl-variation`, as bundled in the `ensemblorg/ensembl-vep:release_116.2` image. The paper's figures were scored against release 115.2 and stay as published; nothing here changes them.

## What changed between the two releases

Ensembl VEP 116 changed the behaviour behind two of the paper's five defects and left the other three as they were.

| Paper's defect | Classes at 115.2 | 116 | Under `116.2` |
| --- | --- | --- | --- |
| A, the splice-region verdict stored by assignment | 1, 2 | `BaseTranscriptVariationAllele.pm:215` and `VariationEffect.pm:87-110` unchanged | the same pair rules apply |
| B, `start_lost` beside `start_retained_variant` | 3, 4 | `VariationEffect.pm:851-963, 1028-1075` unchanged | the same pair rules apply |
| C, a skipped record annotated against its batch | 5, 6, 7, 8 | a record marked `vep_skip` is dropped before the input buffer (`Parser.pm:491-500`, `validate_svf` at `:821-826`; `Parser/VCF.pm:477-481, 555-557, 575`): no row in any format, the warning still written, `--dont_skip` restoring the passage | the batch-comparison classes retire; the record itself is the class `reference_skipped_record` |
| D, transcripts matched by coordinate alone | 9, 10 | 116.1's chromosome-aware overlap (`InputBuffer.pm:286-345`, `_chr_matches_for_vf_overlap` at `:348-358`) keeps a record only when its chromosome, or a breakend mate's, is the transcript's | both masks are no-ops and are not applied |
| E, a mate row read at the record's own coordinate | 11 | `BaseVariationFeatureOverlapAllele.pm:257, 273` unchanged | the same pair mask applies |
| none, `<CNV:TR>` expanded to literal sequence | 12 | `Parser/VCF.pm:382-431` unchanged | the same pair mask applies |

The same chromosome-aware overlap adds three shapes of its own in which 116.2 drops rows vep-rs writes; they are classes 4 to 6 below.

## The classes

Each class has the name the reports print, a one-sentence definition, the Ensembl VEP source it cites, its treatment under the adjusted figure (set aside, or counted and left charged), and the comparator that applies it. A class that counts without setting aside keeps the shape visible without crediting vep-rs for it.

### 1. `reference_skipped_record`

A structural record the reference dropped before its input buffer, marked `vep_skip` for a span over `--max_sv_size` (its `SVLEN`, else its `END`), an ALT type with no Sequence Ontology term, an unsupported multi-allelic list (`<INS>,<DEL>`, `<INV>,<DUP>`, `<DEL>,T`) or a deletion with neither `END` nor `SVLEN`, so it has no reference row in any format; vep-rs annotates it in the default and tab outputs, and its vep-rs rows are set aside, whatever their allele.

Source: `Parser.pm:491-500` (the size test sets `vep_skip` and returns 0 in every mode; `Config.pm:315` holds the 10,000,000 default), `Parser.pm:821-826` (`validate_svf` returns 0 for a `vep_skip` record, so `next()` at `:189` never hands it to the buffer unless `--dont_skip`), `Parser/VCF.pm:477-481` (an ALT type with no Sequence Ontology term, `get_SO_term` at `Parser.pm:663-726` over the table of `ensembl-variation` `Utils/Config.pm:1417-1438`), `:555-557` (an incomplete deletion), `:575` (the mark). The span is the one `ensembl-io`'s `BaseVCF4.pm` `get_end` derives: `SVLEN` first, else `END`, else the start itself, with a breakend's `END` discarded (`Parser/VCF.pm:488-490`); a gnomAD-SV breakend record carries an `SVLEN` to its mate, so a same-chromosome breakend whose mate lies more than 10,000,000 bases away is skipped whole.

Treatment: set aside (both comparators). The class replaces the paper's classes 5 to 8, whose predicates compared the two engines' transcript sets on such a record; against 116.2 the reference has no row to compare.

How the record is recognised. The two comparators recognise it from what each reads. The SNP/indel comparator reads the two outputs and no input VCF, so it applies the output-only rule: 116.2 writes at least one row for every record it keeps, an `intergenic_variant` row when no transcript is in range, so a Location at which vep-rs wrote rows and the reference wrote nothing, under any allele, is a record the reference dropped. At least one vep-rs row at the Location must carry a structural allele (every route to `vep_skip` is structural), and `tandem_repeat` does not admit a Location because the reference keeps a `<CNV:TR>` record and writes it at another Location (the paper's class 12); once admitted, every vep-rs row at the Location is set aside, a sequence allele beside the symbolic one of a mixed ALT list included, because the reference skips the line whole. Its datasets carry no structural record outside the chromosome 21 structural-variant sets the other comparator scores. The structural-variant comparator reads the input VCF and names the record from it: a port of the reference's own routes (`get_SO_term` over the ALT list and `SVTYPE`, the incomplete-deletion test, and the size test over the span `get_end` derives) says which records 116.2 drops. Each such record is confirmed skipped when the reference wrote no row under the record's own Location start and an Allele string the record produces (the Sequence Ontology class of its ALT and of its ALT list, the raw type of an ALT with no class as both engines spell it, a breakend's bracket, own-end and `CHR2`/`END2` mate strings, a sequence ALT as written); exactly that record's vep-rs rows, under those alleles, are set aside. A kept record sharing the start, or the whole Location string, with a skipped one therefore neither hides it nor joins it (gnomAD-SV places a `<CPX>` at the Location of a kept `<DEL>`; a `<NON_REF>` block can start where a kept record starts), and two records at one start producing the same allele are told apart by the end of the Location. The reference's own warnings file names each skipped line, but it is absent on a cached or fixture reference and its record excerpt is truncated, so the records and the outputs are the authority. A disagreement between them stops the comparison with an `ERROR:` naming the record: a record on a route whose own rows the reference wrote (a reference run under `--dont_skip` or under another `--max_sv_size`, declared with `--reference-max-sv-size`, `-1` for no cap); vep-rs structural rows at a Location the reference wrote nothing for that no record on a route explains (a malformed record 116.2 drops for `start > end+1`, which is no `vep_skip` route, or a record missing from the input); or a skipped and a kept record at one start whose alleles and ends coincide, which no output can tell apart.

### 2. The pair classes of defects A and B

The six pair buckets of the paper's registry (`intronic_overcall_swap`, `ppt_overcall_swap`, `frameshift_splice_cascade_swap`, `splice_lastwrite_swap`, `start_cooccurrence_swap`, `covered_splice_region_swap`) apply unchanged: `EXCLUSION_REGISTRY` of `compare_vep_outputs.py` is the pair-rule set of both registries by identity, and `filter_registry_swap_pairs` of the structural-variant comparator applies its excluding rules. Source at 116: `ensembl-variation` `BaseTranscriptVariationAllele.pm:215` with `VariationEffect.pm:87-110` (defect A), `VariationEffect.pm:851-963` and `:1028-1075` (defect B); the files differ from release 115 only in the copyright line.

### 3. The pair classes of defect E and the `<CNV:TR>` representation

`filter_breakend_mate_local_read_pairs` (the paper's class 11; `BaseVariationFeatureOverlapAllele.pm:257, 273`, `VariationEffect.pm:350-358`) and `filter_cnv_tr_expansion_divergences` (class 12; `Parser/VCF.pm:382-431`) apply unchanged in the structural-variant comparator.

### 4. `bnd_own_chromosome_rows_lost`

A bracket breakend whose mate is on another chromosome loses the rows of its own end when a mate-chromosome transcript, in memory from the previous buffer, reaches it first and names its slice: the reference keeps the mate rows and writes nothing under the own-end allele, an order-dependent result.

Source: `AnnotationType/Transcript.pm:122` (`$vf->{slice} ||= $slice ||= $tr->{slice}`: a record's slice is named by the first transcript that reaches it, and in offline mode a record arrives without one), `:125-143` (the slice test: a `chromosome_breakpoint` passes when the transcript's chromosome is the record's slice or any breakend's, `chr` stripped; nothing else passes), `AnnotationSource.pm:119-134` (the features of a region already in memory are returned before those read from disk). When the previous buffer loaded the mate's region and the record's own region is still unread, a mate-chromosome transcript names the slice and every own-chromosome transcript then fails the test.

Treatment: set aside in the structural-variant comparator under the cache authority (`--vep-rs-cache`): the reference wrote a Transcript row under the bracket allele and none under any own-end allele (`N.`, `.N`, `chromosome_breakpoint`), and the vep-rs row's transcript is one the cache files on the Location's chromosome within 5,000 bases of the breakpoint, the reference's own admission rule (`StructuralVariationOverlap.pm:144-160`). Counted and left charged in the SNP/indel comparator, which has no transcript-to-chromosome authority.

### 5. `bnd_synonym_mate_rows_lost`

A bracket breakend whose mate is written with a chromosome synonym (`N[NC_000002.12:321682[`) passes the overlap test through the synonym table but fails the slice test, which compares the raw name with the cache's, so the reference writes nothing under the mate allele.

Source: `InputBuffer.pm:348-358` (`_chr_matches_for_vf_overlap` resolves the mate's name through `get_source_chr_name`), `AnnotationType/Transcript.pm:134` (the breakend's `seq_region_name`, `chr` stripped and nothing else, against the transcript's).

Treatment: set aside in the structural-variant comparator under the cache authority: the mate name, `chr` stripped, is not a chromosome the cache files, the reference wrote rows at the Location and none under the bracket allele, and the vep-rs row's transcript is not on the Location's own chromosome. Counted and left charged in the SNP/indel comparator, where a synonym is any mate name outside the canonical contig set.

### 6. `fasta_named_slice_intergenic`

Under `--check_ref` or `--lookup_ref` with a FASTA whose sequence names differ from the cache's (`chr1` against `1`), the variant's slice is named after the FASTA and every transcript fails the slice test, so the reference writes `intergenic_variant` where vep-rs writes transcript rows.

Source: `Parser.pm:749` (`_get_ref_allele` sets the record's slice from `get_slice`), `BaseVEP.pm` `get_slice` (the slice's `seq_region_name` is the FASTA's), `AnnotationType/Transcript.pm:141` (the test every transcript then fails).

Treatment: counted and left charged in both comparators. The condition is the run's configuration, not a property of any tuple, and it reaches every record of the run; a run that shows the count is re-run with matching sequence names rather than scored.

## The classes retired against 116.2

The structural-variant comparator does not apply these five masks under `116.2`; its report lists them under `masks_not_applied` with the reason.

| Mask | Paper's class | Why it does not apply |
| --- | --- | --- |
| `filter_intended_divergences` | 5 | 116 drops a `vep_skip` record before the input buffer; the reference writes no row to compare transcript sets against |
| `filter_giant_breakend_mate_divergences` | 6 | 116 drops a breakend pair over `--max_sv_size` whole; its mate allele has no reference row |
| `filter_non_ref_batch_divergences` | 8 | 116 drops a `<NON_REF>` record before the input buffer |
| `filter_cross_chromosome_divergences` | 9 | 116.1's chromosome-aware overlap never pairs a record with a transcript on another chromosome |
| `filter_cross_chromosome_orphan_intergenic` | 10 | with no off-chromosome rows to displace it, the reference writes the intergenic row itself |

The SNP/indel comparator's scope class `sv_transcript_selection` (class 5 on a whole-genome input) retires the same way: its pass runs only under `115.2`.

## What the classes reach

Against an Ensembl VEP 116.2 reference produced with the default flags, `reference_skipped_record` reaches exactly the records the reference's warnings file names `line N skipped` for a `vep_skip` reason: on the chromosome 21 structural-variant sets these are the gnomAD-SV `<BND>` records whose `SVLEN` exceeds 10,000,000, every `<CPX>` and `<CTX>` record, and every `<NON_REF>` block; on a hand-built input, a `<DEL>,<DUP>` record is kept as `copy_number_variation` while `<INS>,<DEL>` and `<INV>,<DUP>` are dropped. The two class-D masks, applied under the 115.2 registry against a 116.2 reference, exclude nothing, because 116.1's overlap never pairs a record with a transcript on another chromosome. Classes 4 to 6 are shapes the mechanism admits; whether a reference shows them depends on its input order, its mate names and its FASTA, and the report counts them when it does.

## Choosing the release

`--reference-release` defaults to `116.2` in both comparators. `scripts/concordance/run_concordance.sh` derives it from the Perl Docker image tag, the fixtures directory's provenance or a local checkout's `Constants.pm`; `scripts/concordance/run_clone_measurement.sh` derives it per cell, before the timed runs, from the ground truth's provenance (the suite directory's `provenance.json`, else the `<output>.provenance.json` sidecar beside its output, else the reference set's `provenance.json` one directory up), the image tag first (`release_116.2`) and the cache version when the image is named by digest alone; either accepts `--reference-release` as an override. A reference whose provenance names neither fails the cell before anything is timed or scored (`scripts/concordance/reference_release.py`). The structural-variant comparator also takes `--reference-max-sv-size` when the reference ran with a cap other than Ensembl VEP's default. A report written under `116.2` names its release and lists the classes it applied with their definitions and counts; a report written under `115.2` is the paper's, unchanged.
