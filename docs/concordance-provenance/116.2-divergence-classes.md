# Divergence classes against Ensembl VEP 116.2

A reader choosing which Ensembl VEP release to score vep-rs against finds the taxonomy of the 116.2 registry here. It is every class the adjusted figure sets aside or counts when the reference is Ensembl VEP 116.2. Each class has its mechanism in Ensembl VEP's source at that release. The choice itself is under [Choosing the release](#choosing-the-release).

Source citations name the module and line at the 116 release. That release is the `release/116.2` tag of `ensembl-vep` and the `release/116` branch of `ensembl-variation`, as bundled in the `ensemblorg/ensembl-vep:release_116.2` image. The paper's figures were scored against release 115.2 and stay as published; nothing here changes them.

## What changed between the two releases

Five defects produce eleven of the paper's twelve classes. Ensembl VEP 116 changed the behaviour behind two of them and left the other three as they were.

| Defect | Classes at 115.2 | 116 | Under `116.2` |
| --- | --- | --- | --- |
| A, the splice-region verdict stored by assignment | 1, 2 | `BaseTranscriptVariationAllele.pm:215` and `VariationEffect.pm:87-110` unchanged | the same pair rules apply |
| B, `start_lost` beside `start_retained_variant` | 3, 4 | `VariationEffect.pm:851-963, 1028-1075` unchanged | the same pair rules apply |
| C, a skipped record annotated against its batch | 5, 6, 7, 8 | a record marked `vep_skip` is dropped before the input buffer (`Parser.pm:491-501`, `validate_svf` at `:821-827`; `Parser/VCF.pm:477-481, 555-558, 575`): no row in any format, the warning still written, `--dont_skip` restoring the passage | the batch-comparison classes retire; the record itself is the class `reference_skipped_record` |
| D, transcripts matched by coordinate alone | 9, 10 | 116.1's chromosome-aware overlap (`InputBuffer.pm:286-345`, `_chr_matches_for_vf_overlap` at `:348-357`) keeps a record only when its chromosome, or a breakend mate's, is the transcript's | both masks are no-ops and are not applied |
| E, a mate row read at the record's own coordinate | 11 | `BaseVariationFeatureOverlapAllele.pm:257, 273` unchanged | the same pair mask applies |
| none, `<CNV:TR>` expanded to literal sequence | 12 | `Parser/VCF.pm:382-431` unchanged | the same pair mask applies; it pairs nothing when both runs read a FASTA, and when neither does it pairs only the two symbolic rows of an allele that [states a loss or its run's own length](../divergences/cnv-tr-symbolic-loss-named-a-gain.md), since vep-rs expands the record as the reference does with one and keeps it symbolic without one |

Classes 4 to 16 fall in these groups:

- classes 4 to 6, three shapes the same chromosome-aware overlap adds of its own, in which the reference drops rows vep-rs writes;
- class 7, a row the reference writes for a reference allele;
- class 8, a buffer the reference writes as intergenic;
- classes 9 to 13, five records the reference drops, pairs, or annotates where vep-rs does the opposite;
- classes 14 to 16, three more such records: a `*` ALT annotated from `SVTYPE`, a POS that is not a number numified, and a real `<CNV:TR>` allele dropped beside an `RN=0` one.

None of classes 7 to 13 changed between the releases.

## The classes

Each class has:

- the name the reports print;
- a one-sentence definition;
- the Ensembl VEP source it cites;
- its treatment under the adjusted figure (set aside, or counted and not set aside);
- the comparator that applies it.

A class that counts without setting aside keeps the shape visible without crediting vep-rs for it.

The repository has two comparators. `tools/vep-outputs-compare` scores the SNP/indel datasets and `tools/vep-sv-compare` the structural-variant sets.

### 1. `reference_skipped_record`

A structural record the reference dropped before its input buffer, so that it has no reference row in any format. vep-rs's rows for the record are set aside, whatever their allele. The reference marks a record `vep_skip` for any of these:

- a span over `--max_sv_size` (its `SVLEN`, else its `END`);
- an ALT type with no Sequence Ontology term, a lowercase `<del>` or `SVTYPE=bnd` included, the table's keys being upper case;
- an unsupported multi-allelic list (`<INS>,<DEL>`, `<INV>,<DUP>`, `<DEL>,T`);
- a deletion with neither `END` nor `SVLEN`, or whose start exceeds its end (`END` at POS, `SVLEN=0`, a `SVLEN` that is not a number).

A record is also dropped when `validate_vf` refuses it for an end more than one base before its start or not a number (`END=0`, `END=abc`, a breakpoint's `END=`). vep-rs annotates the `vep_skip` records in the default and tab outputs and refuses the `validate_vf` ones at warning level.

A reference block, one `<NON_REF>` or a list of them (`<NON_REF>,<NON_REF>`), is dropped on the unsupported-type route (`NON_REF`) and is this class. A gVCF variant site (`G,<NON_REF>`), dropped on the same route, is class 9 instead.

Source:

- `Parser.pm:491-501`: the size test sets `vep_skip` and returns 0 in every mode; `Config.pm:315` holds the 10,000,000 default.
- `Parser.pm:821-827`: `validate_svf` returns 0 for a `vep_skip` record, so `next()` at `:189` never hands it to the buffer unless `--dont_skip`.
- `Parser.pm:475-488`: the coordinate checks of `validate_vf`, which return 0 for an end that is not a number or more than one base before the start.
- `Parser/VCF.pm:477-481`: an ALT type with no Sequence Ontology term, looked up by `get_SO_term` at `Parser.pm:663-728` over the table of `ensembl-variation` `Utils/Config.pm:1417-1438`.
- `:555-558`: an incomplete deletion. `:575`: the mark.

The span is the one `ensembl-io`'s `BaseVCF4.pm` `get_end` derives: `SVLEN` first, else `END`, else the start itself, with a breakend's `END` discarded (`Parser/VCF.pm:487-489`). A gnomAD-SV breakend record carries an `SVLEN` to its mate, so a same-chromosome breakend whose mate lies more than 10,000,000 bases away is skipped whole.

Treatment: set aside (both comparators). The class replaces the paper's classes 5 to 8, whose predicates compared the two engines' transcript sets on such a record. Against 116.2 the reference has no row to compare.

#### How the record is recognised

The two comparators recognise the record from what each reads.

The SNP/indel comparator reads the two outputs and no input VCF, so it applies the output-only rule. The reference writes at least one row for every record it keeps, an `intergenic_variant` row when no transcript is in range. A Location where vep-rs wrote rows and the reference nothing, under any allele, is therefore a dropped record when two things hold. Every vep-rs row there names a record in its first column, and no reference row carries any of those names.

At least one vep-rs row at the Location must carry a structural allele, because every route to `vep_skip` is structural. `tandem_repeat` does not admit a Location, because a `<CNV:TR>` record without reference rows at its run need not carry `vep_skip`. With a FASTA, the reference writes an expansion it trims at another Location (the paper's class 12) and writes no row for an empty or unchanged one (`cnv_tr_empty_expansion_dropped`). Without a FASTA, and with one where it writes the expanded allele whole, its rows stand at the run.

Once admitted, every vep-rs row at the Location is set aside, because the reference skips the line whole. A sequence allele beside the symbolic one of a mixed ALT list is included. This comparator's datasets carry no structural record outside the chromosome 21 structural-variant sets the other comparator scores.

The structural-variant comparator reads the input VCF and names the record from it. A port of the reference's own routes says which records the reference drops. The routes are `get_SO_term` over the ALT list and `SVTYPE`, the incomplete-deletion test, and the size test over the span `get_end` derives. Each such record is confirmed skipped when the reference wrote no row under the record's own Location start and an Allele string the record produces. Exactly that record's vep-rs rows, under those alleles, are set aside.

The Allele strings a record produces are:

- the Sequence Ontology class of its ALT and of its ALT list;
- the class term vep-rs prints for an ALT whose letters name a class but whose spelling has no term:
  - `deletion` for `<del>` or `<DEL:>`;
  - `duplication` for `<Dup>`;
  - `inversion` for `<Inv>`;
  - `copy_number_variation` for `<CN=X>`;
  - `insertion` for `<Ins>`;
  - `chromosome_breakpoint` for `<Bnd>`;
- the type string of an ALT whose letters name none, as both engines spell it: the ALT as written (`<CPX>`), or `INFO/SVTYPE` when that names the type (`CPX`);
- a breakend's bracket, own-end and `CHR2`/`END2` mate strings;
- a sequence ALT as written.

#### Where the record's rows are located

vep-rs writes a deletion whose start exceeds its end at the pair, printed low to high and starting one base before the record's own start. The pair is `21:30425650-30425651` for `21 30425650 x N <DEL> . . SVTYPE=DEL;END=30425650`. The comparator locates its rows there.

A kept record sharing the start, or the whole Location string, with a skipped one therefore neither hides it nor joins it. gnomAD-SV places a `<CPX>` at the Location of a kept `<DEL>`, and a `<NON_REF>` block can start where a kept record starts. Two records at one start producing the same allele are told apart by the end of the Location.

#### When the records and the outputs disagree

The reference's own warnings file names each skipped line. It is absent on a cached or fixture reference, and its record excerpt is truncated, so the records and the outputs are the authority. A disagreement between them stops the comparison with an `ERROR:` naming the record. The cases are:

- a record on a route whose own rows the reference wrote, as in a reference run under `--dont_skip` or under another `--max_sv_size`, declared with `--reference-max-sv-size`, `-1` for no cap;
- vep-rs structural rows at a Location the reference wrote nothing for that no record on a route explains: a malformed record the reference drops for `start > end+1`, which is no `vep_skip` route, or a record missing from the input;
- a skipped and a kept record at one start whose alleles and ends coincide, which no output can tell apart.

### 2. The pair classes of defects A and B

The six pair buckets of the paper's registry apply unchanged:

- `intronic_overcall_swap`;
- `ppt_overcall_swap`;
- `frameshift_splice_cascade_swap`;
- `splice_lastwrite_swap`;
- `start_cooccurrence_swap`;
- `covered_splice_region_swap`.

`EXCLUSION_REGISTRY` of `tools/vep-outputs-compare` (`src/rules/mod.rs`) is the pair-rule set of both registries, one table, and `filter_registry_swap_pairs` of the structural-variant comparator applies its rules that set a pair aside.

Source at 116: `ensembl-variation` `BaseTranscriptVariationAllele.pm:215` with `VariationEffect.pm:87-110` (defect A), `VariationEffect.pm:851-963` and `:1028-1075` (defect B). The files differ from release 115 only in the copyright line.

### 3. The pair classes of defect E and the `<CNV:TR>` representation

`filter_breakend_mate_local_read_pairs` (the paper's class 11; `BaseVariationFeatureOverlapAllele.pm:257, 273`, `VariationEffect.pm:350-358`) and `filter_cnv_tr_expansion_divergences` (the paper's class 12; `Parser/VCF.pm:382-431`) apply in the structural-variant comparator.

The `<CNV:TR>` pairing reads four shapes of the reference's row:

- the unit insertion after the run and the unit deletion ending at it, the paper's two;
- a literal substitution across the run or the base after it (`Parser/VCF.pm:505-511, 532-543`):
  - a multi-allelic `<CNV:TR>`;
  - a unit that is not the reference's repeat;
  - a `.` unit read as `N`;
  - an `SVLEN` disagreeing with the unit count;
- the reference's own symbolic `tandem_repeat` row at the run when it ran without a FASTA, where every record is a gain to `copy_number_gain` (`Parser/VCF.pm:516-527`, `Utils/VariationEffect.pm:246-256`). vep-rs gives the symbolic reading without a FASTA too, naming a loss where the record [states one](../divergences/cnv-tr-symbolic-loss-named-a-gain.md) and no direction where it states the run's own length. This shape pairs a vep-rs `tandem_repeat` row with the reference's where the two differ in the direction and coding terms alone.

The literal shape includes a unit that is not DNA, repeated verbatim across the run: `RUS=123;RUC=4` gives the allele `123123123123`. It also includes a loss whose literal reading is a substitution with another coding term. `RN=3;RUS=AG,AG,C;RUC=1,1,1` gives `C` with `protein_altering_variant`. `SVLEN=4000;RUS=CT;RUC=5` gives `stop_retained_variant,3_prime_UTR_variant` in the reference's literal row; without a FASTA both engines write the symbolic row with `coding_sequence_variant,3_prime_UTR_variant`, and vep-rs's pairs with that literal row. With a FASTA vep-rs writes `stop_lost,3_prime_UTR_variant` on the literal allele, one base for a longer span, a pair [`stop_codon_removed_without_stop_codon_test`](../divergences/stop-codon-removed-without-stop-codon-test.md) sets aside ([17](#17-the-pair-classes-that-read-the-two-rows-of-a-pair)).

A multi-allelic record is written whole over the run with a FASTA, one literal tuple for each allele that differs from the run, in both engines. Without one Ensembl VEP writes one symbolic tuple. vep-rs writes a further one with `feature_truncation` where an allele states a loss, and one with no direction term where an allele states the run's own length. `RN=1,1,1;RUS=AGC,AGC,AGC;RUC=4,2,3` gives `protein_altering_variant` for the allele of four units and `inframe_deletion` for the allele of two, and the reference's two tuples each pair with vep-rs's three symbolic tuples. With the reference run without a FASTA and vep-rs with one, no vep-rs tuple is `tandem_repeat`: nothing is paired and the tuples stay charged.

### 4. `bnd_own_chromosome_rows_lost`

A bracket breakend whose mate is on another chromosome loses the rows of its own end when a mate-chromosome transcript reaches it before any transcript of its own chromosome and names its slice. The reference keeps the mate rows and writes nothing under the own-end allele, an order-dependent result.

Source:

- `AnnotationType/Transcript.pm:122`: `$vf->{slice} ||= $slice ||= $tr->{slice}`, so a record's slice is named by the first transcript that reaches it, and in offline mode a record arrives without one.
- `:125-143`: the slice test; a `chromosome_breakpoint` passes when the transcript's chromosome is the record's slice or any breakend's, `chr` stripped, and nothing else passes.
- `AnnotationSource.pm:235-258`: the regions of a buffer are loaded in the order its records first ask for them, each record's own region before its mates', a region listed once at its first request; the transcripts are visited in that order.
- `InputBuffer.pm:191-207, 223-234`: a buffer holds the records of one chromosome.

The loss needs an earlier record of the same buffer, on the record's own chromosome and before it in the input. That record must have asked for a region holding a transcript within reach of the record's mate, before the record's own region was asked for. That transcript names the slice, and every own-chromosome transcript then fails the test. The record alone, with its mate, or under `--buffer_size 1` keeps its own-end rows; `--fork` does not change the result.

Treatment: set aside in the structural-variant comparator under the cache authority (`--vep-rs-cache`) when both of these hold. The reference wrote a Transcript row under the bracket allele and none under any own-end allele (`N.`, `.N`, `chromosome_breakpoint`). The vep-rs row's transcript is one the cache files on the Location's chromosome within 5,000 bases of the breakpoint, the reference's own admission rule (`StructuralVariationOverlap.pm:144-160`). Counted and not set aside in the SNP/indel comparator, which has no transcript-to-chromosome authority.

### 5. `bnd_synonym_mate_rows_lost`

A bracket breakend whose mate's chromosome is spelled in a way the tests after the overlap do not resolve loses its mate rows. Such a spelling is a capitalised prefix or an accession naming another chromosome. The reference writes the own-end rows alone, vep-rs the mate rows too. In `21 30425650 x N N[Chr21:30425700[ . . SVTYPE=BND`, `chr21` is a cache synonym of `21` and `Chr21` is not. This is the worked example of [Defect P](../divergences/defect-p.md#24-a-bracket-breakends-mate-rows-lost-to-an-unresolved-chromosome-prefix).

A mate written with a RefSeq accession on another chromosome (`N[NC_000002.12:321682[`) passes the overlap test through the synonym table but fails the slice test. That test compares the raw name with the cache's. The reference therefore writes nothing under the mate allele. vep-rs resolves the accession through the synonym table, as it resolves the record's own chromosome, and writes the mate rows, which this class sets aside. An accession on the record's own chromosome (`N[NC_000021.9:30425700[`) keeps its mate rows in both engines.

Source:

- `InputBuffer.pm:348-357`: `_chr_matches_for_vf_overlap` resolves the mate's name through `get_source_chr_name`.
- `AnnotationType/Transcript.pm:134`: the breakend's `seq_region_name`, `chr` stripped and nothing else, against the transcript's.
- `StructuralVariationOverlap.pm:86-103`: a mate allele is added only when `_close_to_feature`, `:144-160`, passes. That test compares the mate's `seq_region_name` with the transcript's through `Utils/VariationEffect.pm:111-124`: the synonym table's keys verbatim, else a case-folded equality, which `Chr21` against `21` fails.

Treatment: set aside in the structural-variant comparator under the cache authority, in either of two shapes. In the first, the mate name, `chr` stripped, is not a chromosome the cache files. The reference wrote rows at the Location and none under the bracket allele, and the vep-rs row's transcript is not on the Location's own chromosome. In the second, the mate name is the record's own chromosome spelled with a prefix the reference does not resolve (`Chr21`). vep-rs's mate rows on the own chromosome are then set aside too.

Counted and not set aside in the SNP/indel comparator, where a synonym is any mate name outside the canonical contig set.

### 6. `fasta_named_slice_intergenic`

Under `--check_ref` or `--lookup_ref` with a FASTA whose sequence names differ from the cache's (`chr1` against `1`), the variant's slice is named after the FASTA. Every transcript then fails the slice test, so the reference writes `intergenic_variant` where vep-rs writes transcript rows.

Source:

- `Parser.pm:749`: `_get_ref_allele` sets the record's slice from `get_slice`.
- `BaseVEP.pm` `get_slice`: the slice's `seq_region_name` is the FASTA's.
- `AnnotationType/Transcript.pm:141`: the test every transcript then fails.

Treatment: counted and not set aside in both comparators. The condition is the run's configuration, not a property of any tuple, and it reaches every record of the run. A run that shows the count is re-run with matching sequence names rather than scored.

### 7. `bnd_bare_reference_allele_row`

A breakpoint record that names no mate is held as `N/<BND>`. With no breakend parsed from it, it gets one allele per slash-separated part of that string, the reference base `N` included. Such a record is a bare `<BND>`, or one with `SVLEN`, `POS2` or an `END2` that is not a coordinate, and no bracket ALT. The string is `N/N[21:-7[` when the `END2` is not a coordinate.

The reference therefore writes every row of the record twice under `chromosome_breakpoint`: `ALLELE_NUM=1` for the reference allele and `ALLELE_NUM=2` for the ALT. A reference allele has no variant effect, so vep-rs writes the ALT row once. The worked example is in [Defect F](../divergences/defect-f.md#13-the-reference-allele-row-of-a-bare-breakpoint).

Source:

- `Parser/VCF.pm:491-499`: the bracket mate is built only under `defined $info->{CHR2}` with `END2 || END`; `:499` prepends the reference base.
- `StructuralVariationOverlap.pm:64-77`: `if (!@$breakends) { foreach (split(/\//, $vf->{allele_string})) { add_StructuralVariationOverlapAllele(...) } }`, one allele per part.
- `OutputFactory.pm:2029`: `Allele = $vfoa->{breakend}->{string} || $svf->class_SO_term`, the class term for both.

Treatment: set aside (both comparators). The reference-allele row duplicates the ALT row's tuple, so each comparator's unique-tuple construction drops it before the raw and the adjusted figure. The rows so dropped are counted on the reference's raw output (`count_bare_breakpoint_reference_rows`, shared by both) and reported as the class's set-aside rows, overall and per file. The count is `bnd_bare_reference_allele_rows` in the structural-variant report and the class's `excluded` count in the SNP/indel report. No tuple moves between the two figures for this class.

The same rows carry no `feature_truncation` under `--no_stats`, the reference protocol's flag: `OutputFactory.pm:2029` autovivifies an empty breakend before the terms are computed at `:2034`. With statistics on, `Stats.pm:241` computes the terms first and the rows carry it. A reference produced with statistics on differs from the protocol's on every mate-less breakpoint row.

### 8. `bnd_mate_32bit_buffer_intergenic`

Any coordinate of the reference's input buffer that, with the `--distance` flank added, reaches 2^31 turns every record of the buffer into `intergenic_variant` rows. The coordinate can be a breakend's mate position, a span's end or a record's own position. The records turned are the one that supplied the coordinate, under all its alleles, and every record loaded with it.

A span's end: `21 30425650 x N <DEL> . . SVTYPE=DEL;END=2147483647` under `--max_sv_size -1` gives one intergenic row against vep-rs's 5,074 transcript rows. A record's own position: `21 2147483648 x N N[21:30425700[ . . SVTYPE=BND` gives two intergenic rows against vep-rs's mate rows at the mate. Under the default flank of 5,000 the first such position is 2,147,478,648 and 2,147,478,647 annotates normally; under `--distance 1` the turn moves to 2,147,483,647. No chromosome reaches these positions.

vep-rs holds every coordinate in 64 bits. It writes the breakend's own-end rows and the other records' rows against their transcripts. It writes nothing under the mate allele, as the reference does for any far mate below the bound. The worked example is in [Defect G](../divergences/defect-g.md#14-a-coordinate-at-or-past-2147478648-a-breakend-mate-a-span-end-or-the-records-own-position-turns-the-references-buffer-intergenic).

Source:

- `AnnotationSource.pm:190`: the flank added to each coordinate when the cache regions and the buffer's bounds are chosen, every record's start and end among them.
- `:251-257`: every breakend's mate position is one of those coordinates.
- `:306-309`: `_check_overlap` keeps a transcript against the bounds with the flank added.
- `InputBuffer.pm:386-390`: the mate position inserted into the buffer's interval tree.

Treatment: counted and not set aside in both comparators. The records the shape damages beyond the breakend's own are its neighbours in a buffer whose boundaries the outputs do not record. No tuple is therefore attributed to it. The SNP/indel comparator counts the reference's rows at the Location of a record whose bracket allele names a mate at or past the bound (`BND_MATE_32_BIT_LIMIT`). The structural-variant comparator counts such records from the input, a bracket ALT or `CHR2` with `END2` (else `END`), and the reference's tuples at their Locations (`bnd_mate_32bit_buffer_records`, `bnd_mate_32bit_buffer_reference_tuples`).

A span's end (`SVLEN`, else `END`) or a record's own POS at or past the bound is counted as a mate position is. Both comparators count a reference Location whose start or end is at or past 2,147,478,648, and its rows stay counted, not set aside.

### 9. `gvcf_variant_site_dropped`

A gVCF variant site lists `<NON_REF>` beside its real allele (`A G,<NON_REF>`). The `<NON_REF>` token routes the line to the structural path, where `G/<NON_REF>` has no Sequence Ontology term. The reference drops the site whole, the real allele with it. vep-rs annotates the real allele and reads `<NON_REF>` as the absence of a variant. The worked example is in [Defect H](../divergences/defect-h.md#15-a-gvcf-variant-site-dropped-with-its-real-allele).

Source:

- `Parser/VCF.pm:237-245`: an angle-bracket ALT routes the line.
- `:469-481`: the ALTs joined and looked up.
- `Parser.pm:663-728`: `get_SO_term`, no term for `G/NON_REF`.

Treatment: set aside (both comparators): vep-rs's rows at the site, recognised by the record's shape, `<NON_REF>` beside a sequence allele with no true `SVTYPE`. A block beside a symbolic allele is class 1; under a true `SVTYPE` both engines read the block as an allele of the structural record.

The SNP/indel comparator reads the shape from the input VCFs (`--input-dir`, paired by stem, or `--input-vcf`; the runners pass them). For an ID-less record it reads the shape from the record's own name in vep-rs's output (`CHROM_POS_REF/ALT/<NON_REF>`). It sets aside vep-rs's rows of such a record at a Location the reference wrote nothing for. The structural-variant comparator reads the input record and sets aside vep-rs's rows at the Locations and under the alleles vep-rs's parser writes for the site. There the anchor base is trimmed from an indel and a lone allele is minimised from both ends.

### 10. `dot_breakend_without_svtype_pair`

A dot-notation breakend without INFO/SVTYPE (`N.`, `.N`) takes the sequence rules for its coordinates. The start is POS + 1 when the ALT's length differs from REF's and POS when it does not. The end is POS plus the length of REF minus one. The span the reference writes therefore follows the length of REF:

- the pair `POS-(POS+1)`, with the positions of an insertion, for a REF of one or two bases (`N` or `NA` against `N.`);
- `(POS+1)-(POS+2)` for a three-base REF beside an ALT of another length: `21 30425650 x NAC .N . . .` is `21:30425651-30425652` on both of its transcripts;
- `POS-(POS+2)` beside an ALT of its own length: `21 30425650 x NAC NA. . . .` is `21:30425650-30425652`.

With `SVTYPE=BND` the reference writes the single base at POS + 1, as vep-rs writes it with or without `SVTYPE` and for every REF. When INFO names a mate through `CHR2` and `END2` (`21 30425650 x N N. . . CHR2=21;END2=30425700`), the mate is appended as a bracket allele. The reference then writes the pair under both the `N.` and the `N[21:30425700[` allele, vep-rs the point under both. The worked example is in [Defect I](../divergences/defect-i.md#16-a-dot-notation-breakend-without-svtype-written-as-a-pair).

Source:

- `BaseVCF4.pm:255-276`: `get_start`.
- `:297-317`: `get_end`'s last branch.
- `Parser/VCF.pm:237-245`: the dot still routes the line to the structural path.
- `:491-497`: the mate appended from `CHR2` and `END2`.

Treatment: set aside (both comparators). The reference's row at a two-coordinate span and vep-rs's at the point `chr:(P+1)`, on one feature and under one allele, leave the adjusted figure as a pair. The point is the span's start or the base after it:

- the end of `chr:P-(P+1)` for a REF of one or two bases;
- the start of `(P+1)-(P+2)` for `NAC` against `.N`;
- the second base of `P-(P+2)` for `NAC` against `NA.`.

The allele is the bare `chromosome_breakpoint`, or the `N.` and bracket alleles of a record whose INFO names a mate.

### 11. `missing_alt_annotated`

A record whose ALT column is the missing value `.` is routed to the structural path by INFO/SVTYPE and annotated as an allele. The allele is a `chromosome_breakpoint` at POS + 1 for `SVTYPE=BND` and a deletion over END for `SVTYPE=DEL`. Without SVTYPE the reference writes nothing for it, as vep-rs writes nothing in both cases. The worked example is in [Defect J](../divergences/defect-j.md#17-the-missing-alt-value-annotated-as-an-allele).

Source:

- `BaseVCF4.pm:486-490`: `get_alternatives` returns `['.']`.
- `Parser/VCF.pm:237-245`.
- `Parser.pm:710-711`.

Treatment: set aside in the structural-variant comparator, which reads the input: the reference's rows at the record's Location. The SNP/indel comparator cannot tell them from a record with an allele and counts nothing.

### 12. `non_integer_end_annotated`

An INFO/END that is not an integer (`30425949.5`, `3.0425949e7`) is taken as written and passes `looks_like_number`. The record is annotated with the text in its Location and a fractional DISTANCE; vep-rs refuses the record.

A `SVLEN` that is not an integer reaches the same Location text: `SVLEN=300.7` gives `21:30425651-30425950.7`, and `SVLEN=NaN` gives `21:30425651-NaN` and a JSON `"end":nan`. So does a POS in a non-integer spelling on the sequence path: `21 30425949.0 x A G` gives `21:30425949.0`. For these vep-rs reads the number and writes its rows at it: `SVLEN=300.7` is 300 bases, `NaN` is 0, the pair `21:30425650-30425651`, and the POS is 30425949. The worked example is in [Defect K](../divergences/defect-k.md#18-a-non-integer-end-svlen-or-pos-text-annotated-and-printed).

Source:

- `BaseVCF4.pm:302-309`.
- `:255-276`: a sequence record's POS is kept as its text.
- `Parser.pm:475`.

Treatment: set aside (both comparators): the reference's rows whose Location carries a coordinate that is not an integer. The structural-variant comparator, which reads the input, also sets aside vep-rs's rows of the same record at the number it read (`21:30425651-30425950`, the pair `21:30425650-30425651` for `NaN`, `21:30425949`). Neither side is then charged, and the skipped-record cross-check does not stop on them. The SNP/indel comparator sets aside the reference's text rows alone.

An integer written with a sign or leading zeros (`+30425949`, `030425949`) is the same number. Both comparators read every coordinate as its number before comparing (`canonical_location`, `normalize_location`), so such rows agree with vep-rs's and no class is needed for them.

### 13. `cnv_tr_empty_expansion_dropped`

With a FASTA, a `<CNV:TR>` whose expansion yields no alternate allele, or one equal to the reference run, is expanded to an allele string with no alternate. The reference writes nothing for it, without a warning. Such a record has one of these:

- `RN=.` on its only allele;
- a RUC Perl reads as true that gives zero or fewer repeats (`abc`, `-2`, `0.5`);
- a RUC times the unit length equal to SVLEN.

vep-rs with a FASTA writes nothing for it either; without one it writes the symbolic rows over the run, as the reference does without one. The worked example is in [Defect L](../divergences/defect-l.md#19-an-empty-or-unchanged-cnvtr-expansion-dropped-without-a-row).

Source:

- `Parser/VCF.pm:382-431`: `_expand_tandem_repeat_allele_string`, where `:410` skips an `RN` of `.`, and `:414` and `:419` numify RUC.
- `:516-544`: the VariationFeature built from the string.
- `Parser.pm:553-592`.

Treatment: set aside in the structural-variant comparator, which reads the input. Set aside are vep-rs's `tandem_repeat` rows at the run of such a record. The reference must have written nothing on the chromosome from the base before the run to the base after it.

The record's counts are truncated as Perl's `x` operator truncates them. A unit of no bases repeats nothing under `RUC`, an empty expansion set aside like `RN=.`. Under `RB` it divides by zero in Perl, which ends the reference run, so no reference holds such a record.

A reference run without a FASTA writes the symbolic rows and nothing is set aside. The SNP/indel comparator does not judge the class.

### 14. `star_alone_svtype_annotated`

A record whose only ALT is `*`, the VCF 4.4 marker for a base covered by an upstream deletion, names no allele. With a true INFO/SVTYPE the reference routes it to the structural path, where `*` is outside the VCF 4.4 forms. `SVTYPE` therefore names the type, and the record is annotated from INFO alone.

`21 30425650 x N * . . SVTYPE=DEL;END=30425949` is a deletion over `END`. `21 30425650 x N * . . SVTYPE=BND` is a `chromosome_breakpoint` at POS + 1 written twice. The reference base `N` and `*` are the two parts of `N/*`.

Without `SVTYPE` the reference writes nothing for the record, as vep-rs writes in both cases: no row, the VCF line carried without CSQ, a JSON object with `"most_severe_consequence":"?"`. The worked example is in [Defect M](../divergences/defect-m.md#20--alone-under-a-true-svtype-annotated-as-the-types-class).

Source:

- `Parser/VCF.pm:237-245`: `N*` is not a run of `ACGT` and `SVTYPE` is true.
- `:469`: the allele string `*`.
- `:472-475`: `*` fails `^<?(DEL|INS|DUP|INV|CNV|CN=?[0-9]+)`, so `$type = $info->{SVTYPE}`.
- `StructuralVariationOverlap.pm:64-77`: one allele per part of `N/*`.

Treatment: set aside in the structural-variant comparator, which reads the input. Set aside are the reference's rows at the Location of a record whose ALTs are all `*` and whose `SVTYPE` Perl reads as true. The SNP/indel comparator cannot tell them from a record with an allele and counts nothing.

### 15. `non_numeric_pos_numified`

A structural record whose POS is not a number is annotated at the position Perl's `$start++` makes of the text:

- `.`, an empty column, `0x1D04A1D` and fullwidth digits become 1. `21 . x N <DEL> . . SVTYPE=DEL;END=30425949` is then `21:1-30425949 deletion`, 3,254 transcript rows under `--max_sv_size -1`.
- `30_425_949` becomes 31.
- A negative POS is kept: `21 -5 x N <DEL> . . SVTYPE=DEL;SVLEN=-300` is `21:-4-295 deletion - intergenic_variant`.

A substitution keeps the text and is refused (`Invalid start '.' or end '0' coordinate`).

An indel whose REF and ALT share their first base loses it, and the sequence path's own `$start++` numifies the text the same way: `21 12abc x GA G` is `21:13 - intergenic_variant` and `21 . x GA G` is `21:1`. `21 abc x GA G` is refused quoting the incremented text (`Invalid start 'abd' or end '1' coordinate`). vep-rs refuses every form: `Invalid start '<POS>' or end '<end>' coordinate` for a POS that is not a number, `Invalid POS` for a negative or fractional one.

The worked example is in [Defect N](../divergences/defect-n.md#21-a-non-numeric-pos-numified-by-the-structural-paths-increment).

Source:

- `BaseVCF4.pm:255-264`: `$start++` on the raw POS of a structural record, `:263`.
- `Parser/VCF.pm:306-310, 328-334`: the anchor chop's `$start++` on the raw POS of a sequence indel, `:310` and `:334`.
- `Parser.pm:475-488`: a numified start passes `looks_like_number` and the start-against-end test.

Treatment: set aside (both comparators): the reference's rows of a record whose POS is not a non-negative number, at Locations vep-rs wrote nothing for. A non-negative number is digits, with these parts optional:

- a fraction;
- an exponent;
- a leading `+`;
- surrounding blanks.

A fractional POS is `non_integer_end_annotated` (class 12). A POS above 2^62 - 1, or at it for a structural record whose first base is POS + 1, is a number and not this class. vep-rs refuses the line as past its coordinate bound, and the reference's rows stay charged.

#### How a numified POS is recognised

The structural-variant comparator reads the input and matches the rows by the start the reference prints. That start is POS + 1 on the structural path and POS on the sequence path (`21:-5 G - intergenic_variant`). An anchor-chopped indel prints the incremented start instead, which that match does not reach, so its rows stay charged.

The SNP/indel comparator opens the input only to recognise gVCF variant sites under `--input-dir` or `--input-vcf`, and judges this class from the output alone. It sets aside a reference-only Location whose first coordinate is negative, the one trace no written POS leaves. A start of 1 (a POS numified to 0, which a record at POS 0 also prints) or 31 is recognised by the structural-variant comparator alone.

### 16. `cnv_tr_rn_zero_allele_dropped`

With a FASTA, a multi-allelic `<CNV:TR>` whose `RN` is 0 for one allele expands that allele to an empty part of the joined allele string and loses one of the record's alleles. `21 30425587 x N <CNV:TR>,<CNV:TR> . . SVTYPE=CNV;END=30425596;SVLEN=9;RN=0,1;RUS=AGC;RUC=4` is minimised to `AGCAGCAGC/-` and annotated as the deletion alone, the four-unit gain gone. `RN=1,0` and `RN=2,0;RUS=AGC,AGC;RUC=2,2` are `-/AGC`, the gain alone, the `RN=0` allele gone.

vep-rs annotates both alleles when the `RN=0` allele leads, that allele as the loss of the whole run. A trailing `RN=0` allele is lost to `split` in both engines. The worked example is in [Defect O](../divergences/defect-o.md#22-a-real-cnvtr-allele-dropped-beside-an-rn0-allele).

Source:

- `Parser/VCF.pm:411`: `for ( 1 .. 0 )` runs no iteration, so the allele is undefined.
- `:428`: the alleles joined with `/`, `AGCAGCAGC//AGCAGCAGCAGC`, or a trailing empty part.
- `Parser.pm:978`: `/.+\/.+\/.+/` does not match an empty part, so the string is not treated as multi-allelic.
- `:881`: the first minimised feature is kept.

Treatment: set aside in the structural-variant comparator, which reads the input. The record is a two-ALT record whose `RN` list has exactly one entry the loop at `:411` runs no iteration for. Such an entry is 0 or negative, since `.` leaves no part and is not the shape. The reference must have expanded it under a FASTA, shown by a row at or beside the run under an allele other than `tandem_repeat`.

#### Which rows are set aside for the dropped allele

Set aside are vep-rs's rows at the run for the dropped allele alone. From a vep-rs run without a FASTA these are the `tandem_repeat` rows carrying the dropped allele's direction term. That term is `feature_elongation` when the `RN=0` allele leads and the real allele is a gain. It is `feature_truncation` when the `RN=0` allele trails and the real allele is a gain. An unchanged real allele behind a leading `RN=0` carries no direction term: its rows are the ones that lack the `feature_elongation` of the `RN=0` allele's rows. Where the scored run takes no length from the record and writes one `feature_elongation` tuple for both alleles, that tuple is the dropped allele's.

vep-rs reads a symbolic `<CNV:TR>` allele as a gain unless the record [states a loss or the run's own length](../divergences/cnv-tr-symbolic-loss-named-a-gain.md) for it, and an allele of no repeat sequence states no length. Where the real allele is a gain, the two alleles' rows are therefore one `tandem_repeat` tuple per transcript. No `tandem_repeat` row of vep-rs then carries `feature_truncation`, so a trailing `RN=0` sets nothing aside here.

For example, `RN=0,1;RUS=AGC;RUC=3` over the three-unit run at 30425588-30425596: the reference keeps `AGCAGCAGC/-` alone, `upstream_gene_variant` on ENST00000334068 and `inframe_deletion` on ENST00000390690. vep-rs writes `upstream_gene_variant` for both alleles, `feature_elongation,coding_sequence_variant` for the `RN=0` allele and `coding_sequence_variant` for the unchanged one. The last tuple is set aside, and the `feature_elongation` tuple pairs with the reference's deletion under class 3's `<CNV:TR>` pairing.

From a vep-rs run with a FASTA the rows set aside are those under the real allele's literal sequence when the `RN=0` allele leads. That sequence is `AGCAGCAGCAGC` for `RUC=4`, rebuilt from `RUS` and `RUC` (or `RB`) as the expansion builds it. With a trailing `RN=0` such a run writes what the reference writes.

A real allele that is a loss (`RUC=2`) [states its length](../divergences/cnv-tr-symbolic-loss-named-a-gain.md), so in a vep-rs run without a FASTA its rows name `feature_truncation` and the `RN=0` allele's `feature_elongation`. This class sets neither tuple aside. With a FASTA its literal `AGCAGC` rows are set aside like the gain's.

A trailing `RN=0` beside an unchanged real allele (`RN=1,0;RUC=3`) leaves the reference no alternate and no row, which is class 13. The allele the reference kept is left to class 3's `<CNV:TR>` pairing. When the reference ran without a FASTA this class sets nothing aside. The SNP/indel comparator does not judge the class.

### 17. The pair classes that read the two rows of a pair

Sixteen pair classes read the two rows of a pair. They are, in the order the registry asks them:

- [`structural_deletion_stop_lost_without_stop_codon`](../divergences/structural-deletion-stop-lost-without-stop-codon.md): on a row of a structural deletion over the last three genomic positions of a coding region, the reference writes `stop_lost` without testing a flag or reading a base. vep-rs writes the row's other terms without it on a transcript at whose coding end no stop codon stands. Source: `VariationEffect.pm:1268-1280`.
- [`stop_codon_completed_by_polyadenylation`](../divergences/stop-codon-completed-by-polyadenylation.md): on a transcript whose coding sequence ends one or two bases into its stop codon and whose record shows the model complete, the reference reads those bases as an incomplete terminal codon. vep-rs writes the terms of the row on the stop codon polyadenylation completes. Source: `VariationEffect.pm:1240, 1296, 1548, 1588-1614`.
- [`stop_codon_overlap_without_stop_codon`](../divergences/stop-codon-overlap-without-stop-codon.md): on a transcript without `cds_end_NF` at whose coding end no stop codon stands, the reference reads the last three coding positions as the stop codon and writes `stop_lost` or `stop_retained_variant`. vep-rs writes `frameshift_variant`, an in-frame term or `coding_sequence_variant`. Source: `VariationEffect.pm:1318, 1373-1381, 1400, 1408-1427, 1466-1480, 1508`.
- [`stop_codon_behind_last_residue_without_stop_codon`](../divergences/stop-codon-behind-last-residue-without-stop-codon.md): where an allele keeps every residue and brings a stop codon directly behind the last one, the reference writes `stop_retained_variant` beside the in-frame term. vep-rs writes `stop_gained` beside it on a transcript at whose coding end no stop codon stands. Source: `VariationEffect.pm:1344, 1357`.
- [`start_codon_overlap_without_start_codon`](../divergences/start-codon-overlap-without-start-codon.md): on a transcript without `cds_start_NF` at whose coding start no start codon is shown, the reference reads the first three coding positions as the start codon and writes `start_lost` or `start_retained_variant`. vep-rs writes the row's other coding terms without a start term. Source: `VariationEffect.pm:975-986`.
- [`stop_codon_overlap_genomic_span`](../divergences/stop-codon-overlap-genomic-span.md): on a row with both cDNA positions and a CDS start, the reference writes `coding_sequence_variant` and vep-rs `stop_retained_variant`, both beside `splice_region_variant`. The reference's genomic stop codon overlap reads the last three genomic positions of the coding region and misses a stop base that ends an exon. Source: `VariationEffect.pm:1389-1431, 1616-1649`.
- [`stop_retained_without_stop_codon_test`](../divergences/stop-retained-without-stop-codon-test.md): the reference writes `stop_retained_variant` on a row whose stop codon test it does not make. Such a row has an allele holding a letter that names no base, or a span without a cDNA position at one end or a CDS start. vep-rs writes the same set without the term, with nothing, `coding_sequence_variant` or `frameshift_variant` in its place. Source: `VariationEffect.pm:1290-1324, 1488-1539`.
- [`stop_retained_three_base_stop_codon_test`](../divergences/stop-retained-three-base-stop-codon-test.md): on a row whose stop codon test is made, the reference writes `stop_retained_variant` from the three bases at the old stop position alone. vep-rs writes `coding_sequence_variant` in its place, or, where the reference writes it alone or beside one of `inframe_insertion`, `inframe_deletion` and `protein_altering_variant`, `frameshift_variant` with or without `stop_gained` in the place of those terms. Source: `VariationEffect.pm:1318, 1488-1539`.
- [`stop_codon_removed_without_stop_codon_test`](../divergences/stop-codon-removed-without-stop-codon-test.md): on a row without a cDNA position at one end or a CDS start, the reference writes `stop_retained_variant` with no stop codon test made. vep-rs writes `stop_lost` for the stop codon the record removes. Source: `VariationEffect.pm:1234-1288, 1290-1324, 1508`.
- [`stop_codon_overlap_insertion_range`](../divergences/stop-codon-overlap-insertion-range.md): on a row of an insertion with both cDNA positions and a CDS start, vep-rs writes `stop_retained_variant`, with or without `inframe_insertion`, for the stop codon the insertion keeps. The reference writes `coding_sequence_variant`, or `frameshift_variant` with or without `stop_gained`, because its genomic stop codon overlap moves an insertion's start by the inserted length. Source: `VariationEffect.pm:1389-1431, 1549`.
- [`stop_codon_settled_before_unknown_bases`](../divergences/stop-codon-settled-before-unknown-bases.md): on a row of an allele that holds an unknown base, with one CDS position and one `Codons` cell on both sides, vep-rs writes `stop_gained` and the reference does not. It stands beside `frameshift_variant` on both sides, or in place of the reference's `coding_sequence_variant`, with at most one of `inframe_insertion`, `inframe_deletion` and `protein_altering_variant`. In place of a `stop_retained_variant` the reference writes without its stop codon test, it stands with `frameshift_variant`, one of those three terms or alone. In the cell a stop codon stands before the first codon with an unknown base. The reference translates no such allele and writes no residues; vep-rs's hold the stop at that codon's place. Source: `TranscriptVariationAllele.pm:701`, `VariationEffect.pm:1100-1127, 1211-1232, 1290-1324, 1616-1649`.
  - The class takes a stop codon an insertion keeps as well: there vep-rs writes `inframe_insertion` beside `stop_retained_variant`, and the reference writes that term alone, or `frameshift_variant` or `coding_sequence_variant` on a row of the insertion overlap class.
- [`frameshift_inside_a_held_stop_codon`](../divergences/frameshift-inside-a-held-stop-codon.md): an insertion or a deletion whose length change is no multiple of three and whose first base lies inside the codon of a stop that the transcript's peptide holds as a stop and reads on past (a polymorphic pseudogene's). Ensembl VEP's `frameshift` returns 0 wherever the reference peptide of the allele's codons begins with a stop, which holds for the stop codon no residue follows. On its row the reference writes `coding_sequence_variant` alone, `inframe_deletion` alone, or `inframe_insertion` with `coding_sequence_variant`, and vep-rs `frameshift_variant` in the place of that group. The rule reads the rows' two coding cells, as this section says below. Source: `VariationEffect.pm:1554`.
- [`splice_term_past_the_record_span`](../divergences/splice-term-past-the-record-span.md): on a record whose alternate allele is longer than its reference allele, the reference writes a splice donor, splice acceptor, donor fifth base, donor region, polypyrimidine tract or intron term from positions past the end of the record's span. Where no base of the span lies in a window of that term, vep-rs does not write it, with or without `splice_region_variant` or `splice_donor_region_variant` in its place, unless it is a term of an insertion written after the span. For the intron term the window is the intron. The rule reads the record's alleles, and an insertion written after the span by terms of its own, as this section says below. Source: `VariationFeatureOverlapAllele.pm:405-460`, `BaseTranscriptVariationAllele.pm:117-118, 143-206`.
- [`pachysolen_nuclear_code_read_as_standard`](../divergences/pachysolen-nuclear-code-read-as-standard.md): on a row of a transcript on genetic code 26 whose `Codons` cell holds `CTG` beside a leucine codon, the reference writes `synonymous_variant` with leucine alone in `Amino_acids`. It translates under the last table of its codon module, which holds no table 26. vep-rs reads `CTG` as alanine, as the code gives it, and writes `missense_variant` with alanine on that codon's side. The rule reads the two cells, as the end of this section says. Source: `Bio/Tools/CodonTable.pm:328-338, 412-460`, `TranscriptVariationAllele.pm:712, 736`.
- [`start_codon_removed_without_five_prime_utr`](../divergences/start-codon-removed-without-five-prime-utr.md): on a row of a deletion whose cDNA position and CDS position both start at 1 and whose `Amino_acids` holds no alternate residue, both sides write `inframe_deletion` and vep-rs writes `start_lost` beside it. The reference sets its length test aside for an in-frame deletion, returns from its test of the edited sequence on a transcript without a 5' UTR and from its peptide test on the empty alternate peptide. Source: `VariationEffect.pm:851-904, 906-945`.
- [`start_codon_kept_without_five_prime_utr`](../divergences/start-codon-kept-without-five-prime-utr.md): on a row of an insertion or deletion whose cDNA position equals its CDS position and starts on one of the first three coding bases, vep-rs writes `start_retained_variant` and the reference does not. The term stands in the place of the reference's `start_lost`, or is added where the reference writes no start term. The reference makes its kept-start test behind a 5' UTR alone, and such a row is on a transcript without one. Source: `VariationEffect.pm:851-904, 947-963, 1028-1075`.

#### What the sixteen classes share

Ten differ in a stop codon term or a start codon term on a `Transcript` row. The eleventh differs in `stop_gained` on a row of an allele that holds an unknown base. The twelfth differs in `frameshift_variant` on a row whose reference residues open with a stop. The thirteenth differs in a splice or intron term on a row of a record whose alternate allele is longer than its reference allele. The fourteenth differs in `synonymous_variant` against `missense_variant` on a row of a transcript on genetic code 26.

The fifteenth differs in `start_lost` on a row of a deletion of whole codons from the first coding base of a transcript without a 5' UTR. The sixteenth differs in a start codon term on a row of an insertion or deletion at the start codon of a transcript without a 5' UTR.

Each is one documented difference, with the page its name links to and a row in [docs/intended-divergences.md](../intended-divergences.md). The first stands in its structural-variant calling table, the next twelve, the fifteenth and the sixteenth in its SNP and indel calling table and the fourteenth in its table of caches, species and transcript sets. The sixth to the twelfth and the sixteenth are the stop and start codon entries that page names together.

Treatment: set aside (both comparators). A pair is the reference's tuple and vep-rs's on one Location, Allele, Feature and Feature_type, with different consequence sets. Both tuples of a pair a class takes are set aside, and the pair is counted under the class's name. The sixteen are the `row_pair_rules` of the 116.2 registry in `tools/vep-outputs-compare` (`src/rules/mod.rs`, their predicates in `src/rules/row.rs`); the 115.2 registry holds none. `filter_registry_swap_pairs` of the structural-variant comparator applies them too.

#### How a pair is recognised

A pair reaches these rules when no pair rule of class 2 takes it, and the first of the sixteen that matches takes it. A tuple carries no cDNA or CDS position, so the comparator reads the rows of the two outputs that carry the pair's two tuples. Beside the Allele, the Feature_type and the Consequence, a rule reads from each row:

- the first column, for the record's own alleles;
- the Location;
- `cDNA_position`;
- `CDS_position`;
- `Protein_position`, which the first five classes read, `Amino_acids`, which those five, the eleventh, the twelfth, the fourteenth and the fifteenth read, and `Codons`, which those five, the eleventh, the twelfth and the fourteenth read, each where the row has it.

Every row with the reference's tuple is held against every row with vep-rs's. The pair is taken only when all of them meet the rule.

A pair with a row of fewer than nine columns is left to none of these rules. A row that ends before its `Codons` column, the twelfth, is read without that cell, and none of the eleventh, the twelfth and the fourteenth classes takes a pair with such a row. The fifteenth takes no pair with a row that ends before its `Amino_acids` column, the eleventh. For the eleventh, the twelfth, the fourteenth, the fifteenth and the sixteenth classes the comparators read the two outputs and nothing else: no cache and no input file.

#### How the coding ends are read

The first five classes read the transcript's record in the candidate's cache, given as `--json-cache` to the SNP/indel comparator and as `--vep-rs-cache` to the structural-variant comparator. The record shows which stop codon and which start codon vep-rs reads at the two ends of the coding sequence. A class takes a pair only where vep-rs's coding terms are the ones derived for the row from that reading and from the cells both rows print equal, or from Ensembl VEP's where `Amino_acids` and `Codons` differ as [`alternate_codon_past_the_coding_end`](../divergences/alternate-codon-past-the-coding-end.md) documents. For a sequence allele the derivation also reads the record's own alleles. Without the cache these classes take no pair.

Beside a cache, the five stop codon classes and `start_cooccurrence_swap` take a pair only on a transcript whose record shows the codon at the allele's place. Without a cache they read the two outputs and nothing else.

For `stop_codon_overlap_insertion_range`, a row under an identifier is read as an insertion's by a Location of two neighbouring positions and an Allele of another length than two. Two bases replaced by a sequence of another length are therefore set aside with the insertions.

#### How the record's alleles are read

For `splice_term_past_the_record_span` the comparators read the record's two alleles as well, and no cache. The first column gives the alleles where it spells them. Where it holds an identifier, the SNP/indel comparator reads them from the input records, given as `--input-vcf` or found under `--input-dir`. The structural-variant comparator reads them from the input files under `--input-dir`, the rows of each output from the file it was written from.

With the alleles the rule takes a pair where all of these hold:

- the record is no pure insertion;
- one intron stands beside the span, at a place the rows' cDNA positions allow;
- at that place the record's regions give the reference's terms and the span, or the insertion written after it, gives vep-rs's.

An allele that opens with its whole reference allele changes no base of its span. vep-rs reads it as the insertion it writes, between the span's last base and the base after it, and writes that insertion's terms. On its row vep-rs alone may hold the tract term and the intron term as well, and the reference need hold no term alone. Where that reference allele is one base, Ensembl VEP reads the base as changed, and the reference alone may hold `splice_region_variant` as well. The record alone shows such an allele, and without it no row is read as one.

After one reference base, where the reference's row holds none of the seven, vep-rs alone may hold the donor or the acceptor term. The base is then an intron of one base, and both engines write that term for the same insertion as a record of one alternate allele.

Two rows printed under `--terms display` are read by the three names the seven terms print there, `ESSENTIAL_SPLICE_SITE`, `SPLICE_SITE` and `INTRONIC`, with the record's alleles alone.

Without them it takes a pair where all of these hold:

- the Location holds three or more positions;
- the cDNA positions show each of them in the transcript's sequence;
- vep-rs's row holds none of the six terms.

A span that holds an intron's base, and a Location of two neighbouring positions, then stay differences.

On the genome-wide ClinVar dataset the rule sets aside 1,787 rows on GRCh38 and 386 on GRCh37 with the input records, and 558 and 128 without them.

#### How a frameshift inside a held stop codon is recognised

For `frameshift_inside_a_held_stop_codon` the comparators read the terms, the `Amino_acids` and the `Codons` of the two rows and no other column. The rule takes a pair where all of these hold:

- vep-rs's set holds `frameshift_variant` and the reference's does not;
- the reference's set holds in its place `coding_sequence_variant` alone, `inframe_deletion` alone, or `inframe_insertion` with `coding_sequence_variant`, and every other term stands on both rows;
- both rows hold the same `Amino_acids` cell, whose part before the `/` opens with `*` and whose part after it holds `X`;
- both rows hold the same `Codons` cell, whose two parts differ in length by a number of bases that is no multiple of three.

A pair on which the reference writes `stop_retained_variant` or `stop_lost` is not of the class. A tuple carries the terms alone. The cells that follow them, `IMPACT`, the HGVSp and the plugin cells of a frameshift, are the format comparator's and the plugin tuple scorer's to judge.

#### How a row on genetic code 26 is recognised

For `pachysolen_nuclear_code_read_as_standard` the comparators read the `Amino_acids` and the `Codons` of the two rows. The rule takes a pair where all of these hold:

- the reference's set holds `synonymous_variant` where vep-rs's holds `missense_variant`, and the two sets are otherwise equal;
- both rows hold the same `Codons` cell, two codons of three letters around a `/`;
- exactly one of the two codons is `CTG`, in any letter case;
- the reference's `Amino_acids` is `L` alone;
- vep-rs's `Amino_acids` holds `A` on the side of `CTG` and `L` on the other, around a `/`.

Of the genetic codes vep-rs holds, code 26 alone reads `CTG` as alanine, so vep-rs writes those two cells on a transcript of that code and no other. Where the other codon codes another residue than leucine, both engines write `missense_variant`. Such a row has one tuple in both outputs and is no pair, though its `Amino_acids` differ.

#### How a start codon removed whole is recognised

For `start_codon_removed_without_five_prime_utr` the comparators read the `cDNA_position`, the `CDS_position` and the `Amino_acids` of the two rows. The rule takes a pair where all of these hold:

- vep-rs's set is the reference's with `start_lost` added, and the two sets are otherwise equal;
- both sets hold `inframe_deletion`, and the reference's holds no `start_retained_variant`;
- both rows hold the same `cDNA_position` and the same `CDS_position`, each a range that starts at 1;
- the alternate half of `Amino_acids` is `-` on both rows.

A cDNA position and a CDS position that both start at 1 show a coding sequence that opens on its transcript's first base. The rule reads neither the removed codons nor the triplet left at the start of the coding sequence, so it does not hold vep-rs's term to the genetic code.

#### How a start codon kept without a 5' UTR is recognised

For `start_codon_kept_without_five_prime_utr` the comparators read the `cDNA_position` and the `CDS_position` of the two rows. The rule takes a pair where all of these hold:

- vep-rs's set is the reference's without `start_lost`, where the reference's holds it, and with `start_retained_variant`, and the two sets are otherwise equal;
- the reference's set holds no `start_retained_variant` and vep-rs's no `start_lost`;
- both sets hold `frameshift_variant`, `inframe_insertion` or `inframe_deletion`;
- on both rows the `cDNA_position` and the `CDS_position` are present and equal, and the two rows hold the same positions;
- the `CDS_position` starts at 1, 2 or 3.

A cDNA position that equals the CDS position shows a coding sequence that opens on its transcript's first base. A CDS position that starts at 1, 2 or 3 shows a span that opens on a base of the start codon. The rule reads no base, so it does not hold vep-rs's term to the sequence the record leaves.

### 18. The classes that read the converted cache

`merged_same_dbid_collapse` is the documented difference [Two transcripts of a merged cache that carry one `dbID`](../divergences/merged-same-dbid-collapse.md). Under `--merged` the reference keeps one transcript per `dbID` among those an input buffer loads. A merged cache numbers its two transcript sets apart, so a transcript loses its rows wherever the buffer read a transcript of the other set with its `dbID` first. A record left with no transcript is written as `intergenic_variant`. vep-rs keeps both transcripts. Source: `AnnotationType/Transcript.pm:283-287`, `AnnotationSource.pm:109-145`, `Pipeline/DumpVEP/MergeVEP.pm:94-120`.

`merged_same_stable_id_collapse` is the documented difference [A transcript model the cache carries at two loci](../cache-conversion.md#a-transcript-model-the-cache-carries-at-two-loci-under---refseq-or---merged). Under `--refseq` or `--merged` the reference then keeps one transcript per stable identifier among those the first pass left. It keeps the `ensembl`-sourced one, else the one of the lowest `dbID`. A transcript that shares its identifier with another the buffer loads loses its rows, at another locus or at the same one. vep-rs keeps both. Source: `AnnotationType/Transcript.pm:275, 303-311, 314-343`, `AnnotationSource.pm:109-145`.

Treatment: both are set aside by the SNP/indel comparator, in a comparison that names the converted cache with `--json-cache`. It sets aside vep-rs's rows of each transcript a pass dropped, and the reference's intergenic row at a record the passes left with no transcript. A comparison that names no cache applies neither class, and its reports list neither. The structural-variant comparator holds neither class.

#### How a dropped transcript is recognised

The rows alone cannot tell such a row from one vep-rs writes too many, so the comparator replays the reference's two passes. It reads the buffers from the reference's own output. Every record the reference annotated has a row there, in input order, and the command line of the header gives `--buffer_size` and `--fork`. The input VCF shows by its record count that the reference has a row for every record.

For each buffer the comparator reads from the cache the region files the buffer's records ask for. It reads them in the reference's order: the regions the buffer before left in memory first, then the others as the records ask for them.

Of their transcripts it keeps those that pass the reference's filter at load, as far as the converted record shows, and lie within 5,000 bases of the buffer's lowest and highest position. A RefSeq-set transcript the reference keeps for its display cross-reference alone is left out, since the converted record does not carry it, so no row is set aside for one. The first transcript of each `dbID` stays, and a later one of the other set is dropped. Of the transcripts that stay, those of one stable identifier are then reduced to one: the first whose source is `ensembl`, else the one of the lowest `dbID`.

A transcript that carries the `dbID` of one left out for its cross-reference may be one the reference dropped for that number. No transcript of its identifier is named dropped.

A row of vep-rs is set aside under `merged_same_dbid_collapse` when all of these hold:

- it is a `Transcript` row that vep-rs alone writes;
- the replay dropped its transcript in the buffer of a record at the row's Location;
- that record lies within 5,000 bases of the transcript;
- the reference wrote no row of the transcript at that Location.

Two transcripts of one identifier share the name their rows carry, so `merged_same_stable_id_collapse` judges together the rows vep-rs alone writes of one identifier at one Location and allele. They are set aside when all of these hold:

- they are `Transcript` rows;
- the replay dropped transcripts of the identifier within 5,000 bases of a record at that Location, at least as many as the rows;
- the reference wrote no row of the identifier at that Location that vep-rs lacks;
- where the reference wrote a row of the identifier there, the transcript the replay kept lies within 5,000 bases of the record too.

Two records at one Location share the key of their rows. The conditions on the record then hold for each of them.

The reference's `intergenic_variant` row is set aside where vep-rs wrote rows at its Location and allele and every one of them is set aside so. It is counted under `merged_same_stable_id_collapse` where one of them is, and under `merged_same_dbid_collapse` otherwise.

#### When the class is not applied

`merged_same_dbid_collapse` concerns a reference that ran under `--merged`, as the command line of its header says, and `merged_same_stable_id_collapse` one that ran under `--refseq` or `--merged`. Of any other output nothing is replayed and nothing is written to standard error. The comparator replays such a run only where it can follow the reference line for line. Neither class is applied, and the rows stay differences, in each of these cases:

- the reference's command line holds an option the comparator does not follow, such as `--pick`, `--distance`, `--regulatory` or a `--fork` count above one;
- a row of the reference carries an allele that is no run of bases, or a record lies over a span the reference does not annotate, or at a coordinate past which it writes a whole buffer as intergenic (class 8);
- the comparison names no input VCF, or the input holds a record the reference wrote no row for, which still sits in its buffer and asks for its regions;
- the input VCF holds an empty line before a record, at which the reference ends a buffer;
- a buffer asks again for a region the cache holds no file for, which one process keeps in memory from the buffer before under the transcripts of the file it read next;
- the cache files two synonyms of a record's sequence name.

The comparator then writes to standard error one line with the reason for each class the run concerns.

One case stands apart. Where no transcript of an identifier is `ensembl`-sourced and a `dbID` among them is no plain number, the reference orders them by Perl's reading of that text. The comparator names no transcript of that identifier dropped, and writes nothing.

### 19. `synonym_of_several_sequences_by_hash_order`

A record whose sequence name the reference's cache holds no sequence by, and which that cache's `chr_synonyms.txt` gives to two or more sequences it holds. The file does not say which of them the name stands for. The reference reads the record on whichever of them comes first in the order `keys` returns the name's synonyms. That order changes between runs of one command, so the reference's rows for the record are not reproducible. vep-rs skips the record with a warning.

The class is one documented difference, with a row in the Caches, species and transcript sets table of [docs/intended-divergences.md](../intended-divergences.md). The worked example is in [A name the synonyms file gives to several sequences](../divergences/synonym-of-several-sequences-by-hash-order.md).

Source:

- `CacheDir.pm:254`, `Runner.pm:131`: the cache's `chr_synonyms.txt` is read where the command names no `--synonyms`.
- `BaseVEP.pm:646-656`: the first field of a line and each later field are recorded both ways, as keys of a hash of hashes.
- `AnnotationSource.pm:179`, `AnnotationSource/Cache.pm:90-92`: the cache source asks for the name it reads region files under, among the names the cache holds.
- `BaseVEP.pm:711-716`: the first of the name's synonyms the cache holds is taken, in the order `keys` returns them.
- `BaseVEP.pm:596-621`, `Pipeline/DumpVEP/CreateDumpJobs.pm:200-209`: the dump links names with one level of indirection and writes each linked pair once, which gives one name to several sequences.

Treatment: set aside in the SNP/indel comparator when it is given `--ensembl-cache <dir>`, the Ensembl VEP cache directory the reference run read, under the `116.2` and `116.3` references. The structural-variant comparator and the format comparator hold no rule for the class.

#### What the comparator reads for the class

The comparator takes the sequences the cache holds from its directories, as the reference lists them (`CacheDir.pm:431`). It reads the `chr_synonyms.txt` beside them as both engines read the file: the first field of a line and each later field name each other, one hop. A name is of the class where the cache holds no sequence by it and two or more of the names it is paired with are held. The names come from the reference's own cache, never from vep-rs's converted one.

#### Which rows are set aside and which stay open

Set aside are the reference's rows at a Location under such a name where vep-rs wrote no row at that Location: none among the discordant rows and none in vep-rs's output, which is read once more for those Locations. A run whose cache gives such a name lists the class last among its classes.

These stay differences:

- a record vep-rs wrote a row for, as it does under `--dont_skip`;
- rows on a sequence the cache holds, those vep-rs lost on a sequence its conversion dropped among them;
- every row of a reference output whose header states a command line that names `--synonyms`, or no command line: only a run without that flag read the cache's own file;
- every row of a run that names no such cache, that scores against `115.2`, or whose cache's file gives no such name. Such a run writes the reports it writes without the option.

## What the classes reach

Against an Ensembl VEP 116.2 reference produced with the default flags, `reference_skipped_record` reaches exactly the records the reference's warnings file names `line N skipped` for a `vep_skip` reason. On the chromosome 21 structural-variant sets these are the gnomAD-SV `<BND>` records whose `SVLEN` exceeds 10,000,000, every `<CPX>` and `<CTX>` record, and every `<NON_REF>` block. On a hand-built input, a `<DEL>,<DUP>` record is kept as `copy_number_variation` while `<INS>,<DEL>` and `<INV>,<DUP>` are dropped. The two masks of defect D, applied under the 115.2 registry against a 116.2 reference, set nothing aside. That is because 116.1's overlap never pairs a record with a transcript on another chromosome.

Classes 4 to 6 are shapes the mechanism admits. Whether a reference shows them depends on its input order, its mate names and its FASTA, and the report counts them when it does. Class 7 appears whenever the input carries a breakpoint record without a bracket mate. None of the chromosome 21 structural-variant sets does. Every gnomAD-SV `<BND>` names its mate through `CHR2` with `END` or `END2`, and the synthetic sets write breakends in bracket and dot notation.

Classes 8 to 16 need one of these shapes, and none of the measured sets carries any of them:

- a coordinate past 2,147,478,647;
- a gVCF variant site;
- a dot breakend without `SVTYPE`;
- a `.` or `*` ALT with `SVTYPE`;
- a non-integer `END`, `SVLEN` or POS text;
- an empty `<CNV:TR>` expansion or an `RN=0` allele under a FASTA;
- a POS that is not a number.

## Choosing the release

Each comparator scores vep-rs against one Ensembl VEP release at a time, chosen by `--reference-release`. Under `116.2` they apply the classes on this page, and under `116.3`, the default, the same classes. [docs/intended-divergences.md](../intended-divergences.md) documents each class that sets tuples aside against Ensembl VEP 116.2, with its defect, a worked example on both engines and its counts on the measured sets.

Under `115.2` they apply the paper's twelve classes, classes 1 to 12, unchanged, and write the reports they wrote when the paper was measured, byte for byte. The divergence page keeps those twelve as history, with their numbers, and says which of them release 116 retired.

`scripts/concordance/run_concordance.sh` derives the release from the Ensembl VEP Docker image tag, the fixtures directory's provenance or a local checkout's `Constants.pm`. `scripts/concordance/run_clone_measurement.sh` derives it per cell, before the timed runs, from the ground truth's provenance. That is the dataset directory's `provenance.json`, else the `<output>.provenance.json` sidecar beside its output, else the reference set's `provenance.json` one directory up.

That script reads the image tag first (`release_116.2`) and the cache version when the image is named by digest alone. Either script accepts `--reference-release` as an override. A reference whose provenance names neither fails the cell before anything is timed or scored (`scripts/concordance/reference_release.py`).

The structural-variant comparator also takes `--reference-max-sv-size` when the reference ran with a cap other than Ensembl VEP's default. A report written under `116.2` names its release and lists the classes it applied with their definitions and counts.

The divergence page, [docs/intended-divergences.md](../intended-divergences.md), is written against 116.2. Its classes 1 to 5 and 11 to 24 are the ones a 116.2 report applies, and the paper's classes 6 to 10 stand there as retired, with the release that retired each. Class 5 keeps the paper's number there for the dropped records themselves (`reference_skipped_record`), while the paper's mask for it is among the five retired above.
