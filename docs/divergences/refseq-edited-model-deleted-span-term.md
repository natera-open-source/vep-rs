# A variant inside the bases a RefSeq model's alignment deleted

**The defect in one sentence.** On a RefSeq transcript model whose alignment to the genome deleted bases, a variant lying wholly inside them maps to no transcript coordinate: Ensembl VEP writes the default term `intergenic_variant`, vep-rs the term of the region whose span holds it, `coding_sequence_variant` or the UTR term.

**Why this is a defect.** The row names a transcript, a gene and a strand and carries `BAM_EDIT=OK`, and `intergenic_variant` is defined as a variant between genes. The default is assigned without its own condition: the term's `include` rule requires `within_feature` to be false, and the allele's precomputed predicate hash has `within_feature`, `exon` and `coding` all true. The same engine writes `coding_sequence_variant` for a deletion that reaches one base past the deleted span, so moving a span by one base turns a coding row into an intergenic one.

**What vep-rs does instead.** vep-rs writes the term of the transcript region whose genomic span holds the variant: `coding_sequence_variant` inside the coding sequence's span, and the UTR term inside a UTR's span. The row has no cDNA, CDS or protein position, since the model carries none for those bases. The term Ensembl VEP writes once the span touches a mapped base is the term vep-rs writes throughout the span. On a non-coding model both engines write `non_coding_transcript_exon_variant`: that term reads the exon's genomic span, not the mapper.

**Where it is in Ensembl VEP's source** (`ensembl-vep` at release/116.3, `ensembl-variation` at release/116, `ensembl` at release/116):

- `Bio/EnsEMBL/TranscriptMapper.pm`, lines 168-221, `_load_mapper`: a deletion edit splits the exon's map pair and, at lines 213-218, moves the genomic start past the deleted bases without a cDNA pair for them. The cache stores that mapper (`mapper` under `variation_effect_feature_cache`), so `genomic2cdna` (line 296) returns a `Bio::EnsEMBL::Mapper::Gap` for any span inside them.
- `Bio/EnsEMBL/Variation/BaseTranscriptVariation.pm`, lines 505-528, `cds_coords`, and lines 478-500, `cdna_coords`: the gap is the whole result.
- `Bio/EnsEMBL/Variation/Utils/VariationEffect.pm`, lines 636-669, `within_cds`: true only for a `Bio::EnsEMBL::Mapper::Coordinate` (lines 643-651) or a frameshift intron (lines 655-664), so a gap is neither; lines 671-693, `within_cdna`, the same for the UTR predicates (lines 730-756); lines 1616-1636, `coding_unknown`, which needs `within_cds`.
- `Bio/EnsEMBL/Variation/BaseVariationFeatureOverlapAllele.pm`, lines 454-558, `_bvfo_preds`: `within_feature` 1 (line 480), `exon` 1 (lines 511-516), and a one-gap `cds_coords` is "partly in coding region", `coding` 1 (lines 554-557). Line 285: with no predicate true, `$DEFAULT_OVERLAP_CONSEQUENCE` is assigned.
- `Bio/EnsEMBL/Variation/Utils/Constants.pm`, lines 636-649: the default is `intergenic_variant`, `is_default` 1, `include` `within_feature => 0`, a condition line 285 never reads.

**What correcting it would change.** Every such row would carry the term of the region whose span holds the variant, as the rows that cross the span's edge already do. No position column changes: the model has no coordinate for the bases.

**The class it produces.** `refseq_edited_model_deleted_span_term`: a `Transcript` row of a sequence allele carrying `BAM_EDIT=OK` whose Consequence is `intergenic_variant` in Ensembl VEP and exactly one of `coding_sequence_variant`, `5_prime_UTR_variant` or `3_prime_UTR_variant` in vep-rs, both rows with no cDNA position and the same IMPACT. The format comparator applies it once per row, compares every other field, and leaves a JSON record's `most_severe_consequence` uncompared, since it follows the term. The gnomAD v2.1.1 chromosome 21 dataset (GRCh37) carries 9 such rows under `--refseq`, five on `NM_198689.3` and four on `NM_030582.4` and `NM_130444.3`; the 1000 Genomes high-coverage chromosome 21 dataset (GRCh38) carries 6, all on the COL18A1 models. The committed RefSeq corpora carry none, and the concordance figures, measured on the Ensembl cache, set nothing aside.

## 1. A substitution and a deletion inside the fifteen bases KRTAP10-7's model lacks

**In short.** The single-exon model `NM_198689.3` carries the edit `160 174` with no bases: the genome has fifteen bases at `21:46020656-46020670`, inside its coding sequence between CDS positions 134 and 135, that the model's sequence does not. For the gnomAD v2.1.1 substitution `rs373191083` (`21:46020662 C T`) and the common deletion `rs782183638` of exactly those fifteen bases (allele frequency 0.37), Ensembl VEP writes `intergenic_variant` on the model's row and vep-rs `coding_sequence_variant`, both `IMPACT=MODIFIER` with no position. For the deletion `rs782330177` one base to the left, which also removes the mapped base `21:46020655`, both engines write `coding_sequence_variant` with CDS position `134-?`, and a substitution at `21:46020655` or `21:46020671` is `missense_variant` or `synonymous_variant` on both.

**The same shape on COL18A1.** `NM_030582.4` and `NM_130444.3` share an exon on GRCh38, `21:45504416-45504556`, and both lack the nine bases `21:45504526-45504534` (edits `3387 3395` and `4092 4100`). For the 1000 Genomes record `21 45504526 . C A`, Ensembl VEP writes `intergenic_variant` on both models' rows and vep-rs `coding_sequence_variant`. The unedited sibling `NM_001379500.1`, which has the base, is `synonymous_variant` (CDS 2838, `ccC/ccA`) on both engines, and the deletion `21:45504524-45504529`, which reaches two mapped bases, is `coding_sequence_variant 3376-?` on both. The commands of [Reproducing these examples](reproducing.md#reproducing-these-examples), with `--refseq` and the RefSeq caches, print these rows; `grep NM_198689.3` and `grep -E 'NM_030582.4|NM_130444.3|NM_001379500.1'` select them.
