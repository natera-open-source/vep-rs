# The statistics report's counts against Ensembl VEP

The statistics report differs from Ensembl VEP 116.2 in the counts below; each is an Ensembl VEP behaviour vep-rs does not reproduce, placed in its tier by [Intended divergences from Ensembl VEP](../intended-divergences.md). For the multi-allelic record below, which `--minimal` splits and no transcript overlaps, Ensembl VEP's `[Variant classes]` chart prints `indel 1` and vep-rs's `SNV 1`. Under the default `--buffer_size`, where the kept records fill the buffer exactly and only skipped records follow, `Lines of input read` is `5000` in Ensembl VEP's report and `5001` in vep-rs's. For one record marked for skipping under `--dont_skip`, Ensembl VEP's `--vcf` and `--json` reports print the `Variants processed` label alone and vep-rs's print `1`.

- The `[Variant classes]` key of a record `--minimal` splits is the class of its first alternate allele's trimmed pair, the class both engines print as `VARIANT_CLASS` for the split record. Ensembl VEP computes a record's class once and keeps it (`VariationFeature.pm:1112-1119`). It computes the minimised allele's class when a transcript overlaps the record (`AnnotationType/Transcript.pm:126`) or `--variant_class` is on (`OutputFactory.pm:967`, reached during the rejoin at `:2288`); otherwise its logger meets the record's restored allele string first (`:2290`, `Stats.pm:247`).
- So for `21 5030602 . A G,AT`, which overlaps no transcript, Ensembl VEP's chart prints `indel 1` under `--minimal` and `SNV 1` under `--minimal --variant_class`, the rows being the same in both runs. vep-rs prints `SNV 1` in both. The shape is tier 2 of [Intended divergences from Ensembl VEP](../intended-divergences.md): 1,659 of the chromosome 21 cuts' 15,646,481 records (106 per million) are multi-allelic records whose whole allele string has another class than their first allele trimmed, in 24 corpora. No committed flag set runs `--minimal` with `--stats_text`.
- `Lines of input read` is the parser's final count of data records, skipped records included, as Ensembl VEP's `log_lines_read` describes the row (`Stats.pm:177-190`, "the total number of lines read"). Ensembl VEP stores the count only after a buffer fill that yielded a variant (`InputBuffer.pm:515`; `Runner.pm:480` under `--fork`) and returns before the store on an empty fill (`Runner.pm:424`, `:477`). When the kept records fill the buffer exactly and only skipped records follow, its report keeps the earlier count while its own warnings file names the later line.
- Under the default `--buffer_size` Ensembl VEP's count is `5000` beside `WARNING: line 5001 skipped`; under `--buffer_size 1`, one kept record then one skipped gives `1`. vep-rs prints `5001` and `2`, the parser's final counts. The shape is tier 3: no population cut carries a skipped record, 10 corpora do, and 6 flag sets run `--stats_text`.
- `Variants processed`, and each count the report takes per record with it, counts every record the run writes, in every output format. Under `--dont_skip`, Ensembl VEP's VCF and JSON writers pass a record its parser marked for skipping, a `<DEL>` with neither `END` nor `SVLEN` for one, through as its input line or an `input`-only object, short of the per-record logger (`OutputFactory/VCF.pm:342-345`, `OutputFactory/JSON.pm:229-233`). Its default and tab writers log every record of the buffer (`OutputFactory.pm:288-303`, reaching `:1022`).
- On a one-record input, Ensembl VEP's `--vcf` and `--json` reports print the `Variants processed` label alone and its default and tab reports `1`. vep-rs prints `1` in all four formats, with the same VCF line and, apart from its own version key, the same JSON object for the record. The shape is tier 3: no population cut carries such a record, 6 corpora do, and no committed flag set runs `--dont_skip` with `--stats_text`.
