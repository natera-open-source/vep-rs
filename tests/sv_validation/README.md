# tests/sv_validation/

VCF test suite covering 41 VCF variant categories defined by the generator (`scripts/validation/generate_sv_test_vcfs.py`), spanning VCF v4.1-4.5 allele forms, for both GRCh37 and GRCh38 assemblies.

## Purpose

Exercises vep-rs on every generated variant category, not just the SNVs and small indels covered by the ClinVar benchmark.

## Synthetic VCFs (13 files per assembly, 15,400 variants per assembly)

Generated by `scripts/validation/generate_sv_test_vcfs.py` using assembly-specific reference FASTA and gene coordinates on chr21. Bgzipped + tabix indexed. All variants placed in known coding gene regions (SOD1, APP, DYRK1A, KCNJ6, DSCAM). REF alleles fetched from the actual reference genome via samtools, with one exception: only chromosome 21 is loaded, so the 100 inter-chromosomal breakend mates on chromosomes 1 to 5 in `09_breakends.vcf.gz` carry the placeholder REF `A`. `validate_test_vcfs.py` skips the REF check for those mates.

| ----------------------------- | -------- | -------------------------------------------------------------------------------------------- |

## Real-world VCFs (3 sources per assembly, symmetric)

**These are not committed.** They are large public downloads and are gitignored, so a
fresh clone has the 13 synthetic VCFs per assembly and no `real_world/` directory. That
is a normal state: the integration tests use the synthetic set, and
`scripts/validation/validate_test_vcfs.py` skips its symmetry check when the directory
is absent.

Seed them with `scripts/data/download_real_world_vcfs.sh`, which fetches from the public
hosts below into `${VEP_VCF_DIR:-./.vep/vcf}/<assembly>/sv/` (that directory tree is the
canonical location for every downloaded input, shared with the SNP/indel benchmark VCFs
under `all_variants/`). Link or copy each assembly's `sv/` directory to `real_world/`
here so the validation and comparison scripts, which look under `tests/sv_validation/`,
find them; the exact commands are in "Downloading the real-world VCFs" below. All are
filtered to chr21, bgzipped and tabix indexed. The same three sources must be present
for both assemblies, or a per-assembly comparison is comparing different inputs.

| Source       | GRCh37                        | GRCh38                        |
| ------------ | ----------------------------- | ----------------------------- |
| ClinVar SVs  | `clinvar_sv_chr21.vcf.gz`     | `clinvar_sv_chr21.vcf.gz`     |
| gnomAD-SV    | `gnomad_sv_v2.1_chr21.vcf.gz` | `gnomad_sv_v4.1_chr21.vcf.gz` |
| 1000 Genomes | `1kg_sv_chr21.vcf.gz`         | `1kg_sv_chr21.vcf.gz`         |

## Regenerating

```bash
# GRCh37
python3 scripts/validation/generate_sv_test_vcfs.py --assembly GRCh37 \
  --fasta ${VEP_REF_FASTA_DIR}/GRCh37.fa

# GRCh38
python3 scripts/validation/generate_sv_test_vcfs.py --assembly GRCh38 \
  --fasta ${VEP_REF_FASTA_DIR}/GRCh38.fa
```

Uses `random.seed(42)` for reproducibility. Output defaults to `tests/sv_validation/{assembly}/`.

After generating, bgzip + tabix:

```bash
for f in tests/sv_validation/grch3{7,8}/*.vcf; do
  bgzip -l 9 "$f" && tabix -p vcf "${f}.gz"
done
```

## Downloading the real-world VCFs

```bash
# 1. Fetch (writes to ${VEP_VCF_DIR:-./.vep/vcf}/<assembly>/{sv,all_variants}/)
scripts/data/download_real_world_vcfs.sh [--force]

# 2. Expose each assembly's SV files at the in-tree path the scripts read
ln -s ../../../.vep/vcf/grch37/sv tests/sv_validation/grch37/real_world
ln -s ../../../.vep/vcf/grch38/sv tests/sv_validation/grch38/real_world
```

The download script checks for a local copy first, then an S3 mirror if `$VEP_BENCHMARK_S3`
is set, then the upstream public host. Idempotent, so re-running it only fetches what is
missing. The symlinks are relative, so they survive moving the checkout; a copy works
equally well if your filesystem does not support symlinks. Both `real_world` paths are
gitignored whether they are directories or links, and `.vep/` is gitignored as a whole.

## Validation

```bash
python3 scripts/validation/validate_test_vcfs.py \
  --fasta-grch37 ${VEP_REF_FASTA_DIR}/GRCh37.fa \
  --fasta-grch38 ${VEP_REF_FASTA_DIR}/GRCh38.fa
```

## Concordance Comparison

The vep-rs binary reads `.vcf.gz` files directly (bgzf support built-in). No decompression needed.

`compare_sv_concordance.py` scores the `.vcf.gz` files directly inside `--input-dir`
(default `tests/sv_validation/<assembly>`, so the 13 synthetic files) against Perl VEP
output for the same files in `--perl-dir` and vep-rs output in `--rust-dir`. To score
the real-world files, point `--input-dir` at the `real_world/` directory (or at
`.vep/vcf/<assembly>/sv/` directly) with matching output directories. Pass
`--vep-rs-cache` to activate the cross-chromosome mask; without it the report records
that mask as inactive.

```bash
# GRCh37 synthetic set
python3 scripts/validation/compare_sv_concordance.py --assembly grch37

# GRCh38 synthetic set
python3 scripts/validation/compare_sv_concordance.py --assembly grch38

# GRCh37 real-world set
python3 scripts/validation/compare_sv_concordance.py --assembly grch37 \
  --input-dir tests/sv_validation/grch37/real_world \
  --perl-dir tmp/sv_perl/grch37_real_world --rust-dir tmp/sv_rust/grch37_real_world \
  --output-dir tmp/sv_concordance/grch37_real_world
```
